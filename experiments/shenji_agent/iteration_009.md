## Valid Action Pipeline Analysis
Report: `experiments/shenji_agent/valid_action_pipeline_analysis.md`.

- `training.selfplay._run_single` uses real `train_env.TrainEnv`, loads scenario/map data, calls `env.setup`, then passes side observations into `Agent.step`.
- `Agent.step` reads `observation["time"]`, `role_and_grouping_info`, `operators`, and `valid_actions`.
- If `time.stage == 1`, inherited SDK demo logic returns deployment actions `303` and `333` and does not use normal priority.
- If not stage `1`, Agent iterates `valid_actions[obj_id][action_type]` and can generate `Move`/`Shoot`/`Occupy`.
- Documentation says stage `1` is deployment and stage `2` is normal advancement.
- Minimal SDK probe showed stage remains `1`; repeated `333`, empty actions, and direct normal `Move` actions do not reach stage `2` under failed authentication.
- The smoke scenario is not empty/setup-only by data: stage `1` observations contain `Move` valid action entries, but SDK never permits normal battle advancement.
