# 地图与地理数据剪藏集成评估

本评估从地图展示、地理数据管理和三维传输三个方面核对了现有代码。优先校正影像采集时间，并补充已绘制地图要素的来源说明。以下验收条件供实施时使用。

| 参考材料或工具 | 用途 | 项目现状 | 判断与验收 |
|---|---|---|---|
| 历史专题地图的史料说明 | 区分基于文献绘制的示意线与实测轨迹，并注明出处 | 标绘目录保存标准、引用和精度说明。已绘制要素的编辑菜单缺少来源说明 | 已做：编辑菜单只读显示来源/引用/精度，缺失写“未记录”；`getItem` 透出三项而导出仍只带控制点。`tools/plot_dynamic_test.js` 与 `tools/ui_provenance_test.js` 均在远端 Node 通过 |
| [GeoGuessr](https://www.geoguessr.com/) 影像时间验证 | 区分采集时间、跨日镶嵌区间、入库时间与查询参考日期 | 已修（`f15b635`）：采集区间随栅格写入瓦片登记，`as_of` 取区间末日；旧缓存仅读取时投影为空，退回影像源不带采集时间 | 已做界面分项展示：资源列表与编辑表单分别标示采集区间、检索参考日期、入库时间，无采集记录写“未记录”。远端 `tools/ui_provenance_test.js` 通过并做过三项负向对照 |
| GeoGuessr 固定样例与误差反馈 | 用可复验样例发现地图定位取景回归 | 项目已有按坐标定位和展示误差圈的功能 | [浏览器自检](../situation3d/tools/verify_map_location.py)用合成民用地点验证固定视口取景、零半径、正半径和质心标签，已通过远端 Chromium 测试及五组负向对照 |
| 人工复核的三种展示状态 | 将候选、确认与否决分别呈现 | 项目已记录人工裁决，展示列表会过滤被否决的链接 | 已做：情报列表新增关联复核区块，确认/否决分别计数并逐对列出，每条可撤销（撤销后退回算法判定）；跨案例隔离沿用后端 `case_id` 过滤。`tools/ui_provenance_test.js` 验证呈现、计数、空集合与撤销请求 |
| [CesiumJS 的影像分屏](https://cesium.com/learn/cesiumjs/ref-doc/ImageryLayer.html#splitDirection) | 在同一视角查看两个时期的影像 | 有按日期取数的能力。双期比对需要同一区域的两份资源 | 选一个合规民用样区验证两期覆盖、配准、采集时间和许可。界面验收包括分隔线、缺一期提示和退出恢复 |
| 时点查询与历史快照 | 时点查询回答当时可见的记录，快照用于复现选定的数据与结果 | 观测模型有事件和入库两个时间，现有场景分享链接保存视图状态 | 有审计需求时先做只读查询，迟到记录应被排除。若要复现派生结果，再保存资源与处理版本或冻结结果，并验证后续更正和重算 |
| [3D Tiles](https://github.com/CesiumGS/3d-tiles) 运行统计 | 在固定视点检查首屏时间、请求、处理耗时和内存估算 | 页面有 `?diag=1` 诊断入口，瓦片支持 ZIP 只读体检 | 建议复用入口建立冷、热缓存基线。验证默认模式的开销，区分 API 估算值和实际测量 |
| [3d-tiles-tools](https://github.com/CesiumGS/3d-tiles-tools) 与瓦片层级体检 | 转换旧格式、评估外链与层级误差 | 模型资产已有优化工具。瓦片 ZIP 需保留引用、空间位置和要素元数据 | 有测量证据后在授权副本验证，无断链、覆盖完整、近景精度达标。固定比例调整层级误差和大规模转换均留待测量结果 |
| [glTF Transform](https://gltf-transform.dev/) 与 gltfpack | 优化纹理和网格，对照是否存在更快的离线打包方案 | 单资产已有 glTF Transform 工序 | 沿用现有工具链。只有识别到转换吞吐或纹理资源瓶颈时，才用同一授权样本对照转码时间、传输体积、兼容性和画质 |

地图专题服务、街景游戏和社区题库可以作为交互或训练参考。稳定的民用验收样本用自有、合成或有明确授权的数据。画面资源和瓦片处理工具的授权分别核实。

核验基础为剪藏和仓库代码的静态复查。远端性能、浏览器回归和数据读写测试属于后续验收。
