# 军标图形与态势标绘：调研结论与选型建议

本轮**只出结论**，不进入实现。目标军标（`web/assets/symbols/`）本轮保持现状。

---

## 1. 目标军标：真实装备轮廓（剪影）风格

### 1.1 现状

`tools/gen_symbols.py` 现在生成的是：milsymbol 的 MIL-STD-2525 帧形 + game-icons
（CC-BY-3.0）的图标式图形 + 应用自身的饱和红蓝。它解决了"靠字母 DD/F/AEW 辨认"和
"北约淡彩发白"两个问题，但**图形是图标风格，不是真实装备轮廓**。

### 1.2 可选实现方式

| 方式 | 代表资源 | 许可 | 覆盖 10 类平台？ | 工作量与风险 |
|---|---|---|---|---|
| **A1 CC0 矢量图库** | publicdomainvectors.org（有"navy ship silhouette"多型舰艇剪影）、freesvg.org（military vehicle 合集） | **CC0** | 否，需逐类挑 | 策展工时；风格/朝向/细节粒度不统一，必须归一化 |
| **A2 Wikimedia Commons** | `Category:SVG military vehicle`（117 个军用航空器 SVG）、`File:Mil Land Vehicle Icon.svg`（PD-self，据 M1 Abrams 绘制） | PD / CC0 / CC-BY-SA **混杂** | 否 | 每个文件都要单独核许可；CC-BY-SA 有传染性，混入需谨慎 |
| **A3 svgrepo / 商业图库** | svgrepo（按集合授权）、vecteezy、magnific、iconscout、noun project | 集合级或署名/付费 | 部分 | 授权核对成本高；免费档多要求署名 |
| **A4 官方标准图元** | **JMSML**：`Esri/joint-military-symbology-xml`，**Apache-2.0**，内含 DISA 提供的 2525 SVG 部件（`Frames/`、`Echelon/`、`Amplifier/`、`Appendices/`） | Apache-2.0 | 覆盖**标准图元**而非装备 | **是抽象标准图形，不是真实剪影** —— 适合做帧，解决不了"真实轮廓" |
| **B1 手工绘制 SVG path** | 自绘 | 自有 | 是 | 10 类 × 2 方向 ≈ 20 个轮廓的美术工时；但风格可完全统一 |
| **B2 potrace 描摹** | 公有领域识别手册线图（美军 FM 系列识别图、ONI 舰艇识别图册等） | PD | 是（需找图） | 得到**真正的识别剪影**且风格天然统一（都是线描）；需处理描摹噪点与曲线简化 |
| **B3 运行时 Canvas 生成** | 自研 | 自有 | 是 | 把剪影 path 画进 canvas 作 billboard 纹理（现有管线已是 billboard），便于动态着色/描边 |
| **B4 3D 模型（glTF）** | 免费模型库（Sketchfab CC 等） | 逐个核对 | 部分 | 最"真实"，但与现有 2D billboard 管线不兼容，且资产体积/加载是另一套问题 |

**关键结论：没有任何一个现成库能一次覆盖我们的 10 类平台。**
真实瓶颈不是"下载"，而是**策展 + 归一化**（统一画布、线宽、朝向、细节层级）。
`game-icons` 这类成品图标集之所以能"一次覆盖"，正是因为它本身就是为了一致性而设计的
图标风格——而这恰好不是你要的。

### 1.3 必须先决策的设计冲突

**2525 帧形与真实剪影在语义上是冲突的。**

2525 用**帧形**编码对抗关系（敌方菱形／友方方・圆・拱），而真实装备剪影**自带方向**
（舰艏朝向、机头朝向）。两者叠在一起会互相干扰：菱形里塞一艘带艏向的舰船剪影，
既看不清剪影的细节，帧形也被剪影的尖角破坏。

三条出路，需要选一条：

| 出路 | 对抗关系怎么表达 | 代价 |
|---|---|---|
| **① 剪影不套帧**（推荐） | 只用**颜色**（红/蓝）+ 可选的小角标 | 丢掉 2525 的形状语义；对熟悉 2525 的观众是"不标准" |
| ② 剪影套帧 | 帧形保留 | 剪影必须缩到很小，细节全丢，等于白做 |
| ③ 双图层可切换 | 用户自己选 | 实现与数据都要两套，但汇报时最灵活（"标准模式/外观模式"） |

对"真实装备轮廓"这个诉求，**① 是唯一能让剪影看清的做法**；③ 是它的工程化版本。

### 1.4 建议

1. **先定 1.3 的出路**，再动手——否则做了剪影发现套不进帧，返工。
2. 资源路线建议 **B2（PD 识别手册描摹）+ A1（CC0 图库补齐缺口）+ B1（手工补 1~2 类）**：
   - 描摹路线能拿到**真正的识别剪影**，且线描风格天然统一，是"真实装备轮廓"最贴切的来源
   - 缺口用 CC0 图库补，避免署名义务
   - 只有实在找不到的（如"岸舰导弹发射车"这类具体型号）才手工画
3. 落地形态仍是 **billboard + canvas 纹理**（现有管线不变），只是把 game-icons 的 path
   换成剪影 path；生成器（`tools/gen_symbols.py`）的注入点已经预留好。
4. 若某个平台实在拿不到合规剪影，**退回 2525 标准图元**（A4、Apache-2.0）并明确标注——
   比用来源不明的图安全。

## 2. 态势标绘军标集成

### 2.1 核心判断：标绘军标不是"图片"，是"带控制点的几何"

目标军标（单位符号）是**点状**、可离线成 SVG 的；而态势标绘（进攻轴线箭头、钳形攻势、
阶段线、集结地域、火力扇面、边界…）是**多点图形**：它们的形状由控制点决定，
随控制点变化而重算。所以：

* **不适合**做成 SVG 图片库再去贴图——形状是算出来的，不是画出来的
* **正确形态**是：**几何生成函数（控制点 → 几何） + Cesium 原生几何渲染 + 自建编辑交互**

这也回答了"是不是都得代码绘制"：**几何生成必须靠代码；渲染则交给 Cesium 原生几何**，
不需要我们把每个标绘画成图片。

### 2.2 选型对比（许可与适配均已实测核验）

| 方案 | 版本 | 许可 | 依赖 | 覆盖范围 | 接 Cesium 的方式 | 判定 |
|---|---|---|---|---|---|---|
| **`@zaes/tactical-graphics`** | 4.4.0 | **MIT** | `@turf/*`（约 22 个小包） | **FM 1-02.2 / APP-06**：进攻轴线箭头、阶段线、任务图形、火力扇面、边界… | **直接输出 EPSG:4326 GeoJSON** → Cesium `GeoJsonDataSource` 原生消费；编辑手柄也是 GeoJSON | **推荐打底** |
| `@orbat-mapper/tactical-draw` + `control-measures` | 0.12.0 / 0.30.1 | MIT | 0 / 1 | 2525 / APP-6 控制措施，含**绘制与编辑** | 有 MapLibre / OpenLayers / Leaflet 适配器；**Cesium 适配器不存在**（已实测 404）→ 需自写 adapter | 交互设计可参考，代价高 |
| `@armyc2.c5isr.renderer/mil-sym-ts-web` | 2.10.7 | Apache-2.0 | 0 | **官方美军渲染器**，2525 D/E 全部 + 多点符号（控制措施） | 输出 canvas/SVG，接 Cesium 要自己做几何转换；**包体 32.7 MB** | 权威但重 |
| `missioncommand/mil-sym-ts` | — | Apache-2.0 | — | 同上（上游） | 同上 | 参考 |
| 国产 Cesium 标绘仓库 | 见 2.4 | 多数**无许可** | — | 箭头等若干示例 | 直接是 Cesium 代码 | **多数不可用（见 2.4）** |
| 完全自研 | — | — | 0 | 按需 | — | 每类标绘都是一次几何算法开发 |

### 2.3 推荐方案

**`@zaes/tactical-graphics` 打底 + Cesium 原生 Entity/Primitive 渲染 + 自建最小绘制/编辑交互。**

理由（按重要性）：
1. **它专门补 milsymbol 不做的多点图形**——我们现在正好在用 milsymbol，二者是同一作者
   生态里的互补关系（milsymbol 画点，它画线/面/箭头）。
2. **输出 GeoJSON 而非绑死引擎**，Cesium 原生就能吃，**不需要写引擎适配器**——
   这是与 orbat-mapper 方案相比最省事的地方。
3. **MIT + 只依赖 turf**，授权干净，无传染性。
4. **编辑手柄（handles）也以 GeoJSON 返回**，交互层可以自建，不必迁就它的 MapLibre 适配器。
5. 维护活跃（仓库当日仍有提交）。

### 2.5 缺口与风险

1. **体系不匹配**：`@zaes/tactical-graphics` 是 **FM 1-02.2 / APP-06（美军/北约）**体系。
   若汇报要求**中国军标**样式的标绘（《军队标号》体系），图形规则不同，
   需要自研或用 `cesium-plot-js` 一类国产实现改。**这是最需要你先确认的一点。**
2. **没有现成的 Cesium 编辑交互**：几何生成是现成的，但"拖控制点实时重算"要自己写。
3. **三维贴合**：标绘要贴地形（`clampToGround`）还是浮空？三维视角下细线标绘的可读性
   （宽度随距离衰减、被地形遮挡）需专门设计。
4. **中文字段标注**：标绘上的番号/名称（designation）是英文渲染路径，中文与字体要单独处理。
5. **包体积**：`@zaes/tactical-graphics` 解包 12.5 MB（含文档与示例图），实际运行代码远小于此；
   本仓库是**无构建的 IIFE 前端**，引入 ESM 包需要一次打包步骤或改用 UMD 构建产物——
   这是落地时要先解决的工程问题（与当前 `web/vendor/` 手工 vendor 的做法配套）。
