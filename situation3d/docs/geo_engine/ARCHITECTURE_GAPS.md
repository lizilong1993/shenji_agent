# 引擎架构差距与物理化路线（2026-10-22）

> 结论先行：当前引擎是"**地理数据 + 连续坐标 + 兵棋裁决**"的混合体——地理环境、路径与部分直瞄
> 已经连续化，但**空间权威不统一、目标运动学、平台物理、感知与火力的物理基础**仍是兵棋/游戏抽象。
> 要走向真实物理空间仿真，优先级应为：**空间权威统一 → 运动学/碰撞 → 平台数据模型 →
> 感知与火力物理 → 规划/行为物理 → 海空与环境动力学 → 规模/验证**。战役案例优化推迟。

## 1. 评估基准：什么叫"真实物理世界仿真"

以此 8 条为判据，而非以"案例能否跑完"：

1. **单一空间权威**：地形、水系、建筑、道路与障碍只有一套几何/高程/属性；规划、移动、感知、
   火力全部读同一来源，不存在"规划格说能走、子步说不能走"。
2. **运动学受约束**：目标有位置、朝向、速度、加速度、转弯半径、制动距离；运动由动力学/运动学
   积分产生，不能瞬移、不能原地换向、不能穿过比自身宽的空间。
3. **空间占用与碰撞**：每个目标有真实尺寸/占地（OBB/凸包），与地形、建筑、其他目标发生碰撞；
   "同格最多 4 个单位"这类规则不参与物理。
4. **感知物理化**：传感器有视场、分辨率、探测概率随距离/目标特征/环境衰减；遮挡来自 3D 几何，
   不是格子采样与固定"掩体高度"。
5. **火力物理化**：弹道、穿深、跳弹、破片、冲击波、飞行时间由物理参数推出；裁决表只用于校准
   与兼容。
6. **环境动态化**：天气、能见度、昼夜、烟尘/废墟、海况、潮汐可随时间变化并影响运动/感知。
7. **行为受约束**：规划在运动学与交通规则（车道、限重、限高、单行）内求解；行为层做取舍，
   但不绕过物理。
8. **确定性与可扩展**：同一输入同一结果；规模增长时语义不漂移（例如不因实体数量改变探测节奏）。

## 2. 现有架构与已有基础

```
环境数据 (envpack: terrain/water/buildings/roads + P1 离线管线)
   └─ env/service|pack_env   点查询：高程/水深/landcover/建筑/LOS
        ├─ mobility/profile  平台常量（演示值）
        ├─ mobility/passability 逐点谓词（坡度/水深/建筑/桥隧）
        ├─ mobility/planner  网格 A*（plan_grid = 基础地图格，台海 2 km）
        ├─ sim/motion        沿路线 50 m 子步 + 逐点 passable
        ├─ sim/world         固定 dt、堆叠上限、目标/补给/雷场
        └─ rules/*           观察表、CRT 2d6、间瞄散布表、海空 Pk 矩阵；
                             physics_direct_fire 为可选模型
```

已经具备的"物理侧"资产：

- 连续经纬度与高程、真实 OSM 路网/水域/建筑（P1）、GEBCO 水深、桥隧属性（P4）；
- 50 m 子步防穿越、真实旅行距离与速度因子（P3）；
- `rules/physics_direct_fire.py`：命中概率（散布×目标半径）、入射角/等效厚度/跳弹/穿深/伤害，
  15 个直瞄武器弹道参数、5 级装甲四向 RHA（`ballistics.json`）；
- 事件/CZML/回放、金标准回放与哈希回归、191 项测试。

这些均可复用；问题在于它们**不是默认路径**，且上游的空间与运动仍是抽象层。

## 3. 关键差距（按影响排序）

### G1 空间权威不统一（最致命）
- 规划用 `plan_grid`（台海基础图 2 km 格），裁决用 200 m 规则格，环境数据（envpack 水面/建筑）
  是亚单元 OSM 几何；目标归属按规则格。
- 证据：P6 envpack 场景中 2 km 规划路线落在潟湖/水面上，50 m 子步判不可通行，形成
  "规划—阻塞—再规划"死循环，地面交火为零（P6_cases.md）。
- 影响：任何依赖精度的运动/感知/交战都会出现"能走不能打/能打走不过去"的伪现象。

### G2 运动学与碰撞缺失
- `sim/motion.py` 只对速度做标量加减速（`accel_ms2/decel_ms2`），朝向由路线段直接给出，
  **无转弯半径、无制动距离随载重/坡度变化、无差速/履带转向约束**。
- 无实体间碰撞：`World._enforce_stacking` 以"每规则格最多 4 个"硬性停住多余单位；前端虽有
  OBB 碰撞（`project_vehicle_collision`）但**仿真不使用**。
- 影响：队列/拥堵/狭窄路段/桥梁瓶颈全部失真；车辆可在道路尽头"原地掉头"。

### G3 平台与装备数据不物理
- `mobility/profile.py` 的平台参数为演示常量（履带 10 m/s、转弯率 45°/s 等），质量、功率、
  传动、悬挂、接地压力、越野谱系均无；角色卡注册表也未携带这些物理字段。
- 武器只有 15 个直瞄弹道档；防空/反舰/导弹为 `engagement.SEA_AIR_PROFILES` 合成 Pk；
  装甲仅 5 级 RHA 四向。
- 影响：不同型号差异只能靠手工调常数，无法由数据推导；"真实能力"不可验证。

### G4 感知不是物理过程
- 陆上观察用 `observation.json` 的格子距离表（步兵 10、车辆 25 格），"掩体/隐蔽"以**整数减半**
  表达；`env.pack_env` 的 LOS 以 30 m 采样 + `cover_height`（森林 15 m、居民地 10 m、建筑顶高）
  近似遮挡，无 3D 射线/体素。
- `sim/sensors.py` 的雷达/红外/声呐为名称匹配的固定距离×质量因子；无视场、无探测概率曲线、
  无目标特征（RCS/红外/声学）与海况/天气衰减。
- 影响：探测结果对几何与姿态不敏感，隐蔽/城市/山脊效应粗糙；无法做传感器布设与频谱对抗。

### G5 火力裁决仍以查表为主
- 默认 `direct_fire_model=crt`：2d6 查表 + 修正表；间瞄用散布表随机游走；海空为 Pk 矩阵；
  伤害只有"血值"，无机动/火力/传感器组件损坏。
- `physics_direct_fire` 只覆盖直瞄且有弹道数据的目标，未接入默认路径；无破片/面杀伤/冲击波，
  间瞄与导弹没有飞行段。
- 影响：交战结果与几何/姿态/弹药物理关系弱；同一发弹在不同姿态下差异主要来自随机表。

### G6 环境是静态 2.5D
- envpack 为构建期静态 JSON：建筑=多边形+高度，地形=规则高程网格；无 3D 体块、无地下/隧道
  内部空间、无动态障碍（除雷场）、无天气/能见度/昼夜/海况。
- 影响：城市战、隧道/桥下、烟幕、夜战等真实约束无法表达。

### G7 规划与行为抽象
- 单一全局 A*（8 邻接），无运动学可行性（转弯/坡道/载重）、无车道/单行/优先规则、无编队与
  去冲突；行为靠 `run_geo_demo._assign_orders` 这类演示脚本与固定优先级。
- 影响：路径"能到但开不过去"；大规模时拥堵不可解释。

### G8 时间与规模语义不稳
- 固定 dt 推进；实体数 >50 时传感器按 5 片轮扫（`_compute_table_seen`），**探测刷新节奏随
  兵力规模变化**；确定性依赖这一实现细节。
- 影响：不同规模下同一战术行为结果不可比；性能门槛（500 实体 p95 ~50–100 ms）靠缓存维持，
  物理化后计算量会上升，需要事件驱动/空间分区。

### G9 海空域简化
- 舰船与飞机共用地面式路线（固定 AGL、恒定速度、无转弯半径/爬升率约束）；潜艇深度只是字段；
  海空交战为矩阵 Pk。
- 影响：海空机动、导弹飞行段、防空交战几何均不真实。

## 4. 目标架构（分层，物理优先）

```
┌ 数据层：平台/装备/传感器/弹药 JSON（物理参数 + 溯源）
├ 世界层：统一几何权威（地形/水深/建筑体块/道路属性/动态障碍）+ 3D 空间索引
├ 感知层：射线/视锥 + 探测概率（特征×距离×环境）+ 跟踪/融合
├ 运动层：运动学/动力学积分（地面：自行车/差速+牵引；海：排水/转向；空：能量/转弯率）
│          + 占地 OBB 碰撞、局部避让、地形接触
├ 规划层：分层规划（导航网格 + 运动学可行路径 + 交通规则），行为层输出意图而非坐标
├ 裁决层：物理弹道/穿深/破片/组件损伤（默认）；CRT/观察表为兼容适配器
└ 时间/规模：事件调度 + 空间分区；固定小步长 + 确定性
```

原则：
- **物理层不读兵棋表**；兵棋表只在"兼容模式/校准"里作为参数来源或对拍基准。
- **单一空间权威**：envpack 直接生成导航与碰撞数据，规划/运动/感知共用。
- **数据驱动**：型号差异用平台 JSON 表达，不用代码常量。
- **渐进迁移**：旧模式（`direct_fire_model=crt`、`detection_model=table`）保留为适配器，
  新物理模型通过开关切换，金标准与哈希回归保障可回滚。

## 5. 优先级与阶段目标

### P0 空间权威 + 运动学（建议立即做，约 2–3 周）
1. **统一导航与碰撞数据**：从 envpack 生成 20–50 m 导航场（坡度、水深、建筑体块、桥隧属性），
   规划分两级（粗 500 m 全局 + 细 20–50 m 局部整形），运动端用同一几何做连续碰撞；删除
   `plan_grid=基础地图格` 这一不一致来源。验收：P6 envpack 场景出现地面直瞄且无"规划-阻塞"循环。
   ✅ **2026-10-22 已落地**（`mobility/nav_field.py`，30 m 导航场 + 包内细 A* + 跨包粗路线
   包内细化；`World.plan_route` 统一入口）。P6 envpack：地面直瞄 0→23、无规划-阻塞循环、
   p50 574→126 ms。详见 `P0_1_nav_field.md`。
2. **运动学基础**：实体增加 heading/速度/加速度状态，转弯半径、制动距离、坡道/载重速度曲线；
   以 OBB/凸包做建筑与实体间碰撞，替代"每格 4 个"的堆叠规则（保留为软上限告警）。
   ✅ 无穿模/瞬移；狭窄路段可见排队；同 seed 哈希稳定。
   ✅ **2026-10-22 已落地**（`mobility/kinematics.py`、`sim/collision.py`）：偏航率/曲率限速/
   制动回推速度剖面、OBB 实体碰撞（yield 排队）与足迹水域检查、出生/下船去重叠、
   `crowding` 软告警。1440 tick 探针穿模/瞬移/航向跳变均为 0。详见 `P0_2_kinematics_collision.md`。
3. **平台数据 v1**：`platforms/*.json`（尺寸/质量/功率/速度曲线/转弯/装甲面/特征/传感器/武器），
   现有 profile 常量作为默认回退；校验 schema + 单测。验收：从 JSON 能重建现有单位行为。

### P1 感知与火力物理（约 3–4 周）
4. **3D 感知**：建筑体块/地形 BVH 射线、传感器视场与探测概率曲线（RCS/IR/声学特征、海况/
   能见度），跟踪/融合；观察表作为 legacy 模式。验收：山脊/街区/烟幕场景探测结果随几何变化。
5. **物理火力默认化**：直瞄全武器数据化；间瞄弹道弧+落点散布+破片；弹药/引信/飞行时间；
   组件损伤（机动/火力/传感器）替代单一血值；CRT 作为校准与兼容。验收：几何/姿态改变命中与
   穿透的单调性、与物理基线对拍。
6. **运动学规划**：在 P0 导航场上做可行路径（转弯半径、倒车、排队、单行/限重/限高），
   行为层给意图（目标/节奏/风险）而非直接坐标。验收：规划路径可由运动层无阻塞执行。

### P2 海空与环境动态（约 4–6 周）
7. 舰船/飞机动力学（转弯半径、爬升/能量、海况、甲板作业），导弹飞行段与制导。
8. 天气/能见度/昼夜/烟尘/废墟与动态障碍；传感器与机动受其影响。

### P3 规模、确定性、验证（持续）
9. 事件驱动时间、空间分区/并行；确定性哈希；规模扩展时探测节奏不随实体数变化。
10. 物理化验收：无穿模/瞬移计数=0；转弯半径与制动距离符合参数；感知 ROC 与公开/实测数据
    校准；交战结果可复现；300/500 实体性能门槛保持。

## 6. 复用与迁移策略

- **复用**：P1 envpack 数据与缓存、`geo.geodesy`、`mobility` 接口、`Route/事件/CZML`、
  `physics_direct_fire` + ballistics、角色卡注册表、测试/金标准框架。
- **改造**：`GridPlanner` → 分层运动学规划器；`motion.integrate` → 状态空间积分器；
  `World._enforce_stacking` → 碰撞求解；`sensors/detection` → 物理感知（表模式保留）；
  `combat/engagement` → 物理裁决（CRT/Pk 保留为适配器）。
- **不做**：继续为具体案例调脚本/锚点/演示行为；把兵棋表继续扩展到新武器（除非作为校准数据）。
- **案例**：战役插件保持"薄适配器"：只描述单位、目标、初始态势；行为与物理由引擎负责。

## 7. 风险与注意事项

- 物理化后性能显著下降：需要空间分区、事件调度与批量射线；P0 阶段先保证正确性，性能门槛
  按新模型重新标定。
- 数据可得性：平台/弹药/传感器物理参数需公开或估计数据，需在 JSON 中标注来源与置信度。
- 与庙算 SDK 的关系：SDK 的 CRT/观察表仍可作为"校准/兼容模式"，但不能成为新引擎的语义核心。
- 迁移风险：保留 legacy 开关与金标准回放，逐模块切换（空间→运动→感知→火力）。
