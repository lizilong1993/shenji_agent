# 性能：300/500 实体 p95 达标（2026-10-22）

> 提交 `960591f`；基准脚本 `scripts/bench_geo_engine.py`，回归门槛 `tests/test_bench_regression.py`。

## 1. 方法

- 场景：60×60 / 200 m 网格，红蓝均势重型坦克（seed=1，武器 36），无指挥官/战术，纯引擎步进。
- 口径：先跑 `--warmup 10` 预热（缓存/索引填充），再统计 `--ticks` 内每 tick 耗时；
  p95 取排序后 `int(n*0.95)`。预热前的冷启动尖峰单独记录，不混入验收。
- 语义回归：同 seed 事件 JSON 的 sha256 前 16 位固定，优化前后必须一致。

## 3. 优化内容（均不改裁决语义）

1. **LOS 单元对持久缓存**（`World._los_cell_cache`）：地形/建筑静态，`cell_line_of_sight(ca, cb)`
   结果可跨 tick 复用；键按无序单元对，上限 50 万条。命中率约 85%（71.6k 次查询仅 10.9k 次实算/30 tick）。
2. **检测结果持久缓存**：陆上对陆上的可探测性只依赖（观察者/目标、单元对、目标隐蔽状态），
   缓存键 `(obs, tgt, cell_obs, cell_tgt, concealed)` 跨扫描切片保留，静止部队第二遍起零成本；
   跨域（海/空）对仍按单元对短缓存。
3. **单 tick 小缓存**：`cover_at` 按实体缓存、`env.grid.cell_of` 按实体缓存（每 tick 清空）。
4. **距离复用**：`_compute_table_seen` 已算的 cube 距离传入 `can_detect/can_observe`，
   省去重复 `rule_distance`（71k 次/30 tick）。
5. **基准脚本**：新增 `--warmup`、事件哈希与进程峰值内存（rss）；回归测试固定 300/500 配置的
   p95 <100 ms 与事件哈希。

## 4. 剩余热点与后续

- 冷启动：首 tick 500 实体约 1 s；可预计算静态可见性/预热缓存（不影响稳态）。
- `_engage`/`_best_target` 在传感器优化后成为次热点（300 实体 30 tick 0.25 s），可做候选裁剪/批量化。
- 缓存内存：检测 50 万条、LOS 50 万条上限，约数十 MB 量级；超限停止写入（退化为逐次计算）。
- 未引入 Numba/C++；若后续实体 >1000 或 tick <0.1 s 需求，再考虑向量化 LOS/批量检测。
