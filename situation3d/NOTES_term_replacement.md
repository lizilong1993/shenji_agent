# 术语替换：态势 → TS、战场 → ZC

本文记录这次全局术语替换的完整依据：规则、逐处清单、有意保留的位置与理由。
清单由 `tools/apply_term_rename.py --report --inventory NOTES_term_replacement.md`
生成，位于下方标记之间；标记之外的文字是手写分析，重新生成**不会**覆盖它。

## 替换规则（最终版）

| 原词 | 替换为 | 说明 |
|---|---|---|
| 态势 | `TS` | 字面替换，不做分词判断 |
| 战场 | `ZC` | 同上 |
| 战场态势（相邻） | `ZCTS` | 早期曾写作 `ZC-TS`，已按用户要求去掉连字符 |
| 机动态势 | `机动TS` | 早期作为豁免保留，已按用户要求替换 |
| 产品名「三维战场态势生成系统」 | `三维ZCTS生成系统` | 早期豁免，已取消（含网页 `<title>`） |

工具同时把已存在的 `ZC-TS` 归一为 `ZCTS`，因此**重复运行是收敛的**（幂等）。

ASCII 拼写 `situation` / `Situation`（219 处 / 42 文件）**不动**：它是标识符不是中文
术语；改名会牵动 `SituationHost` / `SituationPanel` 等公开全局名，属另一轮的重命名工作。
代价是代码里存在「中文文案叫 TS、标识符叫 Situation」的两套称呼。

## 结构性判定：这是纯文本替换，不是 schema 变更

排查过、均**无**命中：Python/JS 变量名与函数名、JSON **键名**、CSS 类名与选择器、
HTML `id`/`class`。已提交的数据文件（`engine/data/roads/*.json` 76 MB、
`vector/*.geojson`）grep 计数为 0。因此替换不可能改变代码行为或运行期字段。

## 有意保留的位置（现在只剩一类）

**没有术语豁免了。** 唯一不改的是夹在 `term-replace:keep-start` / `keep-end` 之间的
**说明文字**——它们必须引用原词才讲得清，例如 `style.css` 里解释 `.ts-*` 类名前缀与
「态势→TS」同形但无关的那两行；一旦被替换成「TS→TS」就完全读不通。
这类行在清单里标 `KEEP (标记区间)`，与"漏改"明确区分。

早期两条豁免的现状与后果：

| 早期豁免 | 现状 | 后果 |
|---|---|---|
| R1 产品名 | **已取消** | 对外名称变为 `三维ZCTS生成系统`，含网页 title |
| R2 本体论 `机动态势` | **已取消**，改为 `机动TS` | ⚠ `engine/data/intent_ontology_v2.json` 是 `code/shenji_agent/Shenji/ontology/intent_ontology_v2.json` 的内嵌副本，而**后者不在可改范围内**，两处从此口径不一致；重新同步本体论会把改动覆盖回去。这是有意接受的代价，不是遗漏。 |

## 风险与不处理项

| 项 | 判定 | 处置 |
|---|---|---|
| `ts-*` CSS 类名前缀 | 与「态势→TS」**同形但无关**（那是"目标状态"栏的命名空间） | 类名不动，在 `style.css` 注释注明歧义 |
| `TS` / `ZC` 既有占用 | 替换前独立词 `TS`/`ZC` 在全部文本文件中均为 **0** 次 | 无冲突 |
| `TS` / `ZC` 行业歧义 | `ZC` 亦可指侦察/中程/指挥 | 属既定要求，仅记录 |
| 生成数据集 | `web/data/*.json` 内嵌引擎字符串（`inference_model.levels[].name`、`parents[].name_zh`、`case_name`、`overall.note`） | **每次规则变更后重建**两案例；陈旧案例数据集已清理 |
| `docs/庙算平台资料汇总.md` | 位于 `situation3d` 子树之外，且是第三方资料汇总 | 不处理（不在本仓库跟踪范围内） |
| 目录名 `三维态势系统/` | 仅本地存在，远端仓库对应目录是 ASCII 的 `situation3d/` | 不改（改名的路径连锁代价远超收益） |
| Git 历史提交信息 | 改写会破坏哈希 | 不改；新提交起使用新术语 |
| `tools/shots/`、`web/vendor/`、`web/tiles/` | 二进制与第三方 | 不处理 |
| `tools/apply_term_rename.py`、本文 | 规则定义与清单本身必然含原词 | 预期残留 |

## 工具自身的两个 bug（都已修，记在这里免得重犯）

1. **整串替换吞掉上下文**：第一版把「三维战场态势生成系统」**整串**放进替换模式、回调
   返回 `ZC-TS`，结果整串被替换——"三维" 与 "生成系统" 一起丢了，README/title/brand 全
   变成 `ZC-TS`。正确做法是模式只匹配「战场态势」这一小段。
   教训：替换表里放"整句"而不是"词"。
2. **预筛写死中文词导致归一规则失效**：加上 `ZC-TS → ZCTS` 后，预筛仍只查 `态势`/`战场`，
   于是"已经替换过、只剩 `ZC-TS`"的文件被直接跳过，归一形同虚设。改为用模式本身
   `_PAT.search` 预筛，以后再加规则也不会漏。
   另有一处同类问题：清单"未被改写但含术语"的那一遍原先用 `convert(单行)` 判断，而单行
   看不到 keep 标记，标记区间内的行既不记为改写也不记为保留——从清单里彻底消失。

* 运行时：两案例 `pageErrors` 为空；产品名、界面文案、数据集层级名与本体论父类名均已
  使用新术语。

  证明是重建而非新旧混用。
