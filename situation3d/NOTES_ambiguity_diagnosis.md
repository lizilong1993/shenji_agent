docs(situation3d): 定量定位模型歧义不足的真正原因（推翻我此前的归因）

我此前多轮把"模型歧义表达能力不足"归因为**编码器容量不足**（需要论文的
Entity MLP + Causal Transformer + GRU + CIGR）。本轮做了定量测量，**该归因是错的**，
真正的原因是**投影/封顶把每帧本来多元素的集合压成了单元素或空集**。

测量（taiwan_landing，stride 24）：逐个样本拆开看每一环
--------------------------------------------------------
| 量 | 结果 |
|---|---|
| `u*` 目标 | min 0.000 / med 0.667 / max 1.000，**sd 0.262** |
| `u` 模型输出 | min 0.369 / med 0.563 / max 0.694，**sd 0.075**，range 0.324 |
| δ | 0.441 – 0.502（中位 0.465） |
| **投影前的集合大小** | 0:7, 1:46, **2:153, 3:142, 4:216, 5:163**, 6:43, 7:40, 8:22, 9:23, 10:63, … |
| 距阈值 0.05 以内的 | 2:112, 3:116, 4:196, 5:193, 6:88 … |

关键结论：**投影前，模型对多数帧给出 2–5 个候选**（中位约 4），
这与 CES 目标（平均 2.975）量级一致。也就是说兼容度头**并非表达不出歧义**。

问题在投影那一步
----------------
* `ever` 取"曾通过阈值"的**并集**，所以在长序列上会迅速积累到很多候选；
* 但 `cap = len(prev) if prev else len(eligible)` 让集合**只能单调收缩**，
  且一旦某帧为空就把该目标标记为 `dead`、此后恒空。
* 于是"某帧恰好只过 1 个"或"某帧恰好为空"会**不可逆地**把该目标锁死在单元素/空集。
  这正是实测看到的 taiwan 空集 8488 / 单元素 11549 / 歧义仅 3019。

即：**我为了满足"集合只减不增"这条不变量而加的封顶与 dead 终态，
本身消灭了歧义。** 论文的收缩保证依赖 Proposition 里"打分序在区间内不变"的假设，
而该假设在噪声打分下不成立；我用封顶强行达成不变量，代价就是把集合压扁。

因此先前"需要更强编码器"的说法**不再站得住**：编码器给出的表征是可用的，
需要重新设计的是**投影的时间语义**——例如允许在证据确实变化时重开候选
（真正的 no-reentry 只应约束"被判定为不支持"的意图，而不是约束"权重暂时低于阈值"
的意图），同时另找一个不靠封顶来表达"候选集不增"的办法。

这是一次**归因纠正**，不是功能提交：本轮不改行为、不引入未验证的改动。
下一步必须先在 `intent_set_selftest` 里补一条"投影前 vs 投影后集合大小"的对照断言，
否则这个压扁效应下次仍会被误读成模型的锅。
