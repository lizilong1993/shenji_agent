1. Project identity

This repository is a Python land-wargame AI project built around the Miaosuan / Land Wargame SDK. It is no longer just an SDK demo repository. The current codebase has two parallel responsibilities:

- Runtime agent logic that plays inside TrainEnv.
- A model-production pipeline for supervised training, self-play evaluation, league gating, and artifact publishing.

The active mainline appears to be a hybrid policy:

- Rule-based action generation still exists in ai/agent.py.
- Learned intent and situation models are loaded through ai/policy.py from ai/weights/model_manifest.json.
- Formal promotion decisions are based on league/self-play artifacts, not only training loss or a single ad hoc evaluation run.

4. Runtime architecture

Runtime AI flow:

- ai/agent.py constructs an Agent.
- Agent.setup(...) receives scenario/map/state/setup info.
- Agent creates a Map helper from basic_data / cost_data / see_data.
- Agent configures LearnedPolicy with:
  - faction
  - artifact directory
  - policy profile
- During step(...):
  - observation is cached
  - learned policy observes enemy state history
  - controllable operators are resolved
  - rule-based priority order scans valid actions
  - action generation may use learned scoring via LearnedPolicy

Important runtime behaviors:

- The default policy profile is baseline.
- If user_name is CurrentAI and no profile is explicitly given, Agent.setup will prefer challenger.
- If learned artifacts are requested but not loadable, the agent falls back to rules and disables AI optimization.

7. Evaluation and promotion pipeline

The formal evaluation path is training/selfplay.py plus training/evaluate.py.

Key behavior:

- Builds paired scenario lists from land_wargame_sdk/Data/Data/scenarios/*.json
- Resolves map ids and map buckets
- Runs paired matches candidate vs incumbent
- Summarizes:
  - overall point estimate
  - bucketed results
  - CI95
  - Elo-equivalent metric
  - learned policy coverage
- Writes artifacts such as:
  - match_results.json
  - rating.json
  - promotion.json
  - exploitability.json
  - participants.json
  - summary.md
  - map_list.json

Promotion-gate thresholds in configs/selfplay_sota_stop.yaml:

- overall_point_estimate_min: 0.60
- overall_ci_lower_min: 0.55
- complex_point_estimate_min: 0.60
- complex_ci_lower_min: 0.55
- min_learned_path_coverage: 0.30
- min_move_path_coverage: 0.20
- min_shoot_path_coverage: 0.20
- elo_delta_lower_min: 35.0
- max_bucket_regression: 0.03
- max_exploiter_win_rate: 0.45
- consecutive_windows: 2

Very important project rule:

- program.md states that stop/ready decisions must come from the self-play/league evidence path, not from supervised metrics alone.
