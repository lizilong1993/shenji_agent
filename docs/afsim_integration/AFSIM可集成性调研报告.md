## 0. 一句话结论

**AFSIM 对本项目有价值，但价值集中在“模型与架构模式”，不在代码。** 整套 WSF 是 C++/Qt 工程（约 200 万行；有第三方称源码包约 10 GB，未核实），官方文档标注 CUI 且许可带使用主体限制，代码级移植既不可行也不建议；可操作的是把**传感器探测、航迹处理、导弹制导、任务处理器状态机**这四类模型按公开公式重实现进 Python 引擎，或在机构具备授权的前提下把 AFSIM 作为**外部仿真服务**经 DIS / 外部控制接入。

| 路线 | 判定 | 主要原因 |
|---|---|---|
| 代码级移植（把 WSF 源码/插件搬进本项目） | **不建议，通常也不可行** | 许可使用主体限制；C++11 + Qt/VTK；约 200 万行、源码包体积大（第三方称约 10 GB，未核实）；插件 ABI 与现有 Python 引擎不兼容 |
| 进程级集成（AFSIM 当外部仿真服务） | **通常不可行（除非机构在授权范围内）** | 需机构符合许可资格；需场景转换、时序桥接、DIS/外部控制链路；适合“要高保真、可接受双栈运维”的场景 |
| 模型级重实现（按公开公式重写） | **推荐** | 无代码许可风险；与现有 Python 引擎同栈；可按案例逐步替换“射程圆”模型；工作量可控 |

## 1. 本项目基线（对照基准）

### 1.1 现有能力

situation3d 当前是 **Python 3.8 零依赖引擎 + CesiumJS 1.145 前端 + 静态服务**，完全离线运行：

- 案例注册与数据集生成：`engine/cases.py`、`engine/scenario.py`，每案例导出 JSON，前端不复制推理口径；
- 三级态势推理：`engine/inference.py`，L1 目标级（状态/意图/威胁度/告警）、L2 编组级、L3 区域级；
- 威胁度 = 装备权重 + 接近度（按最近对方**武器有效射程**衰减）+ 覆盖度（按对方**传感器标称距离**加权：`Σ 3·(1−d/R)`）；
- 地理计算：WGS84 球面距离/方位/插值（`engine/geo.py`）；
- 前端：离线分级影像/DEM、WSF3D/3D-GloBFP 建筑、军标、目标模型、CZML 运动与特效、标绘、动态图层、目标跟随、鸟瞰等。

geo-engine 分支（按项目既有记录）已推进到物理化底座 P0–P6：空间权威、运动学、平台数据、环境包、桥隧/雷场/间瞄规则、车辆 OBB 碰撞与车道；**明确短板是导弹制导、部分 F0–F2 规则与工程兵**。

### 1.2 能力缺口

| 能力 | 现状 | 缺口 |
|---|---|---|
| 传感器探测 | 型号标称探测距离；按距离线性/指数衰减计入威胁度 | 无雷达方程、RCS、信噪比、检测概率、虚警、干扰、地形遮蔽、扫描周期 |
| 航迹处理 | 直接使用目标真实位置 | 无“检测→航迹”链路、测量噪声、卡尔曼/α-β 滤波、航迹相关/融合、航迹保持与删除 |
| 武器交战 | 有效射程 + 开火/命中/击毁特效 | 无发射包线（LAR）、弹道/气动、制导律、导引头截获、引信与毁伤概率 |
| 任务/C2 | L1–L3 规则推理与告警 | 无任务分配、平台行为状态机、指挥链、思考/评估时延、任务取消与重分配 |
| 通信/数据链 | 无 | 无链路预算、连通性、时延/丢包、路由、任务消息传递 |
| 事件与回放 | 前端时间轴回放 CZML/JSON，已有事件展示与交战特效 | 缺仿真侧的探测/跟踪/分配事件分类、统一事件日志与批量统计 |

这张表基本就是 AFSIM 能补的部分。

## 2. AFSIM 是什么

| 维度 | 内容 |
|---|---|
| 定位 | AFRL 维护的**任务级/交战级**多域军事仿真框架；公开资料称其由 WSIM（武器系统仿真）与 Warlock（人在回路）演进融合；覆盖陆、海、空、天、电、网 |
| 版本 | 公开中文资料以 **2.9.x** 为主（2025–2026 年的教程与安装实证均基于 2.9.0） |
| 技术栈 | 面向对象 **C++11**，工具链用 **Qt/VTK**；插件机制；内置类 C#/Java 的脚本语言；**离散事件**调度 |
| 规模 | 约 **200 万行**代码（2021 年口径）；第三方文章称源码包约 **10 GB** |
| 核心应用 | `mission`（批量/基准仿真）、`engage`（面武器效能与目标脆弱性）、`post_processor`（后处理/报告）、`sensor_plot`（覆盖范围/天线增益/杂波表）、`weapon_tools`（武器模型开发与发射计算器） |
| 套件工具 | **Wizard**（想定 IDE）、**Warlock**（实时/人在回路）、**Mystic**（回放分析）、EVT Reader、Mover Creator |
| 互操作 | **DIS（IEEE 1278）**、**HLA（IEEE 1516）**、XIO 外部输入输出、外部控制插件（TCP/UDP）、MATLAB/Simulink、STK |
| 文档标注 | WSF 官方 Doxygen 首页明确标注 **CUI（受控非密信息）**，并声明数据的使用、传播或披露受随附 README 与 LICENSE 限制 |
| 核心抽象 | 应用 → 场景 → 仿真；仿真实体是**平台**，平台挂 **mover / sensor / weapon / comm / processor** 等组件；传感器产生**航迹**，航迹进入**航迹处理器**，**任务处理器**按航迹驱动有限状态机 |

> 版本口径：本表的组件/工具/互操作信息来自 2.9.x 相关资料；第 4 节的任务处理器、航迹语义等细节主要引自 2.6.1 中文文档翻译。2.9 可能调整属性名与能力，落地前应按 2.9 文档复核。

### 2.1 值得借鉴的三条数据流设计

1. **传感器 → 航迹管理器 → 任务处理器 → 武器** 的单向链路：传感器只负责“看到”，航迹管理器负责相关/融合/滤波，任务处理器只读航迹做决策。本项目目前是“真实位置直接进推理”，缺的正是中间这层“感知层”。
2. **按航迹实例化的状态机**：每个航迹一份状态机，状态可以是“等目标进入射程 / 等传感器截获 / 等武器引爆”，配合 `time_to_think`、`evaluation_interval`、`number_of_servers` 表达指挥决策时延与计算资源约束。这是比“每帧规则判断”更可扩展的 C2 建模方式。
3. **任务消息可丢失**：分配/取消任务经通信网络传递，受距离与干扰影响可能丢失；受让人被击杀则任务自动取消。这为“通信降级下的指挥控制”提供了现成语义。

## 4. 四个高价值可移植点（模型级）

### 4.1 传感器探测：把“射程圆”换成“雷达方程 + 遮蔽 + 扫描”

AFSIM 的雷达传感器不是单一距离阈值，而是由发射功率、天线增益、波长、RCS、系统损耗、噪声系数、带宽、检测门限共同决定，并叠加杂波、干扰与地形遮蔽。对本项目，最小可用版本只需四步：

1. **雷达方程**：`Pr = Pt·Gt·Gr·λ²·σ / ((4π)³·R⁴·L)`，`SNR = Pr / (k·T·B·F)`；`SNR ≥ 门限` 判定检测，门限按虚警概率设定，检测概率可用 Swerling 模型给出平滑曲线。
2. **视距与地形遮蔽**：4/3 地球半径视距 + 沿视线在 DEM 上采样，低空/掠海目标会因此出现“近了反而看不到”的效应。
3. **天线与扫描**：方位/俯仰视场、扫描周期、重访间隔；扫描间隙内的目标不应每帧都被“看到”。
4. **干扰**：噪声干扰的 J/S 比直接抬高等效噪声，压制距离随干扰机功率与几何变化。

输出不要直接给“看到/没看到”，而是 `检测概率 / 首次发现时间 / 航迹质量`，再喂给 L1 威胁度。这样“预警机看得远但无武器”的既有口径可以保留，同时威胁度不再是纯几何。

### 4.2 航迹处理：感知层与推理层解耦

AFSIM 的航迹管理器负责：相关（同一目标多次检测合成一条航迹）、融合（多传感器）、滤波（卡尔曼/α-β/α-β-γ）、保持（丢失后外推）、删除（超过清除间隔）。本项目可直接落一个 6 状态卡尔曼（位置+速度），加上：

- 航迹 ID 与生命周期：`tentative → confirmed → coasting → dropped`；
- 测量噪声按传感器类型配置（雷达距离/方位误差、EOIR 角度误差）；
- `lock count` 语义：任务激活期间航迹不被清除；
- 上报接口：任务处理器只读航迹，不读真实位置。

这一步完成后，L1 的“被探测数量/最近对方目标”才真正来自传感器，而不是几何真值。

### 4.3 武器交战：3DOF 弹道 + 比例导引 + 发射包线

AFSIM 的武器体系包含显式/隐式武器、制导与弹道导弹、导引头、发射计算器与毁伤效果。对本项目，建议先做空空/防空两类：

- **3DOF 质点弹道**：推力/阻力/重力，质量随燃料变化；不必上 6DOF；
- **制导律**：比例导引（PN）或增强比例导引（APN），导引头截获距离/视场作为门限；
- **引信与毁伤**：近炸半径 + Pk 表（可按交会角/距离查表）；
- **发射包线（LAR）**：离线预计算“可发射区/不可逃逸区”，前端作为图层叠加，既服务推演也服务指挥界面；
- **事件驱动特效**：开火/命中/击毁由仿真事件触发，复用现有 combat FX。

这一块工作量最大，但也是“从态势展示走向交战推演”的关键；建议按“先防空、后空空、再反舰”的顺序，先用公开弹道/气动数据标定射程与包线形状。

### 4.4 任务处理器：每航迹一个行为状态机

AFSIM 的任务处理器是“每航迹一个 FSM + 思考时间 + 评估周期 + 服务器数”的结构。对本项目可简化为：

- 平台级行为状态机：`巡逻 → 发现 → 跟踪 → 交战 → 规避 → 返航`；
- 任务队列：上级分配任务带优先级与时限，平台按“思考时间”延迟响应；
- 任务取消/重分配：目标被摧毁、航迹丢失、平台被击毁时自动释放；
- 计算预算：`number_of_servers` 可映射为“同时处理的航迹数上限”，避免大规模场景下每帧全量计算。

这比在 `inference.py` 里堆规则更可扩展，也能自然产生“指挥延迟”这类态势现象。

## 5. 集成路线（若机构具备授权）

如果确需 AFSIM 的高保真模型，现实方式是**进程级集成**，而不是把 WSF 嵌进 Python：

```
AFSIM mission（批处理）/ Warlock（可选 HITL）
        │  .evt 事件文件 / .aer 回放 / DIS PDU / 外部控制 TCP-UDP
        ▼
桥接服务（Python）
        │  事件 → 本项目 JSON/CZML；指令 → AFSIM 外部控制
        ▼
CesiumJS 前端 / geo-engine
```

要点与风险：

- **许可资格**：先确认机构是否在授权范围内；不在范围内则整条路线不成立。
- **运行环境**：AFSIM 2.9 提供 Windows 安装包（本文所引资料以 Windows 为例）；Linux 侧需按官方构建说明自行编译，Qt/VTK 依赖较重；Windows 路径不能含中文/空格。
- **场景转换**：本项目的案例 JSON 需要转成 AFSIM 的文本场景（平台、传感器、武器、航路、任务）；这是一次性但不可忽略的工程量。
- **时序与一致性**：AFSIM 是离散事件、可变步长；前端是固定帧回放。需要事件时间戳对齐与插值，否则会出现“位置跳变”。
- **接口方式**：AFSIM 的集成接口以 `mission` 批处理、外部控制插件（TCP/UDP）与 DIS/HLA 为主；是否有额外的 Python 互操作需按具体版本与分发文档核实。即便存在 Python 接口，许可与部署限制仍然成立，不能据此认为代码可直接嵌入本项目。
- **双栈运维**：多一套 C++ 工具链、许可管理、日志与版本，长期成本高于模型级重实现。

结论：只有当“必须使用 AFSIM 已验证的传感器/武器模型做对外比对或交付”时，才值得走这条路线；否则优先模型级重实现。

1. **不要下载第三方转发的“完整源码/工具包”**。CSDN、网盘等渠道的 2.9.0 源码包可能本身就不符合分发条款，引入项目会放大合规风险。
2. **不要把 AFSIM 源码、二进制、场景文件或脚本复制进本项目仓库**，也不要把 AFSIM 作为依赖写进 `requirements`/构建脚本。
3. **可以借鉴的是公开文献中的模型思想与公式**（雷达方程、卡尔曼滤波、比例导引、有限状态机、DIS/HLA 标准），这些属于通用知识；实现须是“干净重写”，并在代码注释中记录公式出处，不引用 AFSIM 代码或数据。

建议在启动任何相关开发前，由项目法务/保密部门对 AFSIM 分发包内的 README/LICENSE 原文做一次确认；本报告不构成法律意见。

## 7. 建议实施顺序（相对工作量）

| 阶段 | 内容 | 相对工作量 | 产出 |
|---|---|---|---|
| P0-a | 传感器探测：雷达方程 + 视距/地形遮蔽 + 扫描周期 + J/S | M | 检测事件、首次发现时间、覆盖图初版 |

| P1-a | 任务处理器：行为 FSM + 任务队列 + 思考时延 | M | C2 行为与指挥延迟 |

## 8. 验收标准（建议）

1. **传感器**：给定 RCS/发射功率/高度，探测距离与公开资料/型号标称值的偏差可解释；地形遮挡场景下 LOS 判定正确；单帧计算不突破现有性能预算。
2. **航迹**：检测中断后按设定外推并在超时后删除；多传感器同一目标合并为一条航迹；任务激活期间不被误删。
3. **制导**：拦截包线形状合理（近界/远界/不可逃逸区）；命中率随距离/机动过载单调变化；参数改动可复现。
4. **回归**：关闭新模型时，当前演示案例（ZY1 / TW1 / TW2）的数据集与前端表现不变；开启新模型后差异可逐事件解释。
5. **合规**：仓库中无 AFSIM 源码/二进制/场景文件；公式出处与参数假设有据可查。
