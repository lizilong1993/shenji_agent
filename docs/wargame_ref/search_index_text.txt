=== 庙算·陆战指挥官是一个战术级实时制陆战兵棋平台，同时是一个智能博弈AI开发平台。 (#ai) ===
<p>庙算·陆战指挥官支持人类选手进行日常训练和支持大规模在线竞赛的组织与对抗。另一方面，本平台为AI提供开发与评估环境，支持AI通过本平台分发的离线环境实现单机上的开发和调试。同时提供了AI的在线上传测试等功能，以便在网络化平台上开展机机、人机、和人机混合等模式的实时对抗与测评。</p>
=== Frequently Asked Questions (faq/) ===

=== 环境如何进入推演阶段 (faq/#_1) ===
<p>当所有Agent都发出“结束部署动作后”，环境进入推演阶段</p>
=== 如何判断当前在部署阶段还是推演阶段 (faq/#_2) ===
<p>检查态势中<code>observation["time"]["stage"]</code>，值为1说明在部署阶段，值为2说明在推演阶段</p>
=== 为什么SDK运行输出“did not pass authentication”，或没有输出“did pass authentication”? (faq/#sdkdid-not-pass-authenticationdid-pass-authentication) ===
<p>原因：SDK版本过时 解决方法：</p> <ol> <li>删除land_wargame_train_env python库</li> <li>重新安装land_wargame_train_env-*.whl</li> <li>如果~/.engin_config文件存在，请删除</li> </ol>

=== AI开发 (reference/) ===
<p>本部分文档面向庙算陆战指挥官实时制陆军战术级兵棋AI的开发者，主要描述本系统AI开发SDK的使用、 兵棋环境的接口说明。本开发文档适合具有Python编程经验，以及强化学习基础知识，且对本平台推演规则具有一定了解的开发者。</p> <p>本平台为开发者提供了用于本兵棋平台AI开发的SDK（包括环境类、AI基类、DemoAI、以及本地启动AI与环境的入口文件），并提供了在线复盘查看和AI上传服务等功能。</p>
=== 动作 (reference/actions/) ===
<p>agent的<code>step</code>函数必须返回一个动作列表。 列表中的每个元素<code>action</code>表示的是该agent当前帧要进行的动作的确切信息，需要遵守正确的数据结构。 而后此动作列表将作为<code>TrainEnv.step</code>的参数传入环境。</p> <p>每个动作的正确结构见下文。</p>

=== <code>BaseAgent.step</code> (reference/apis/#baseagentstep) ===
<p>功能：agent在对局过程中需要调用<code>step</code>接收态势以及输出agent动作列表。以下参数均为在正式网络对抗时，引擎一定会向此接口提供的参数，单机离线时完全由开发者自行决定是否提供。</p> <p>参数说明：</p> 参数名 数据类型 说明 observation dict 态势数据 <p>返回值：</p> 数据类型 说明 List[dict] agent返回生成的符合格式要求的动作列表。详见动作数据 <p>示例：（来自DemoAI） 在<code>BaseAgent.step</code>中开发者需要体现AI的策略。<code>BaseAgent.step</code>函数传入的参数是态势信息,输出的则是agent的动作列表。因为agent所作出的一切动作都必须要通过step函数来返回，所以开发者需要在<code>BaseAgent.step</code>函数中完成接受态势以及生成动作的功能。态势数据和动作数据见态势数据以及动作数据。 <pre><code>def step(self, observation: dict):
    self.observation = observation  # save observation for later use
    self.team_info = observation["role_and_grouping_info"]
    self.controllable_ops = observation["role_and_grouping_info"][self.seat][
        "operators"
    ]
    communications = observation["communication"]
    for command in communications:
        if command["type"] in [200, 201] and command["info"]["company_id"] == self.seat:
            if command["type"] == 200:
                self.my_mission = command
            elif command["type"] == 201:
                self.my_direction = command
    total_actions = []

    if observation["time"]["stage"] == 1:
        actions = []
        for item in observation["operators"]:
            if item["obj_id"] in self.controllable_ops:
                operator = item
                if operator["sub_type"] == 2 or operator["sub_type"] == 4:
                    actions.append(
                        {
                            "actor": self.seat,
                            "obj_id": operator["obj_id"],
                            "type": 303,
                            "target_obj_id": operator["launcher"],
                        }
                    )
        actions.append({
            "actor": self.seat,
            "type": 333
        })
        return actions

    # loop all bops and their valid actions
    for obj_id, valid_actions in observation["valid_actions"].items():
        if obj_id not in self.controllable_ops:
            continue
        for (
            action_type
        ) in self.priority:  # 'dict' is order-preserving since Python 3.6
            if action_type not in valid_actions:
                continue
            # find the action generation method based on type
            gen_action = self.priority[action_type]
            action = gen_action(obj_id, valid_actions[action_type])
            if action:
                total_actions.append(action)
                break  # one action per bop at a time
    return total_actions

=== 状态与态势 (reference/observations/#_1) ===
<p>State and Observation</p> <p><code>state</code>一般代表环境当前的所有状态。<code>observation</code>一般情况下代表对于某个智能体可观测的态势。<code>observation</code>是<code>state</code>的子集。</p> <p><code>TrainEnv</code>的<code>step</code>函数返回的<code>state</code>，表示当前环境的所有状态合集。状态合集有红方蓝方绿方态势组成：<code>state[0]</code>代表的是红方态势，<code>state[1]</code>代表的是蓝方态势,<code>state[-1]</code>代表的是绿方态势。 agent代码的<code>step</code>函数接受的参数是态势<code>observation</code>，它封装了当前时间，此agent能观测到的所有盘面信息，包括算子信息、裁决信息等。以下是态势最外层的数据结构以及他们代表的含义。</p> Field Type Description <code>actions</code> <code>list</code> 上一步接收到的动作 <code>cities</code> <code>list</code> 各个夺控点的信息 <code>communication</code> <code>list</code> 通信相关信息 <code>jm_points</code> <code>list</code> 间瞄点信息 <code>judge_info</code> <code>list</code> 裁决信息 <code>landmarks</code> <code>dict</code> 地标信息，雷场，路障 <code>operators</code> <code>list</code> 算子信息 <code>passengers</code> <code>list</code> 乘员信息 <code>role_and_grouping_info</code> <code>dict</code> 玩家信息和编组信息 <code>scenario_id</code> <code>int</code> 想定ID <code>scores</code> <code>dict</code> 分数信息 <code>terrain_id</code> <code>int</code> 地图 ID <code>time</code> <code>dict</code> 时间信息 <code>valid_actions</code> <code>dict</code> 当前态势下的可做动作信息 <code>extra</code> <code>dict</code> 额外信息

=== 环境本地使用流程 (reference/usage/#_1) ===
<p>本地单机通过运行根目录下run_offline_games.py脚本启动引擎和本地Demo agent对抗。 agent生成动作后，env调用step接收双方的动作，并生成下一步的state以及done。state[RED]为红方态势，state[BLUE]是蓝方态势，state[GREEN]是包含了蓝方和红方的全局态势数据，在全局态势中，双方所有的算子信息全部可见。</p> <p>在本地推演对战的实际过程中，开发人员对态势信息（state）和动作信息（actions）的内容和流动有完全的获取，修改，控制权；态势，数据和动作数据的具体格式参照态势数据说明以及动作。但是在线上网络对抗中，agent只能获得由对抗引擎发送的本方态势信息，env也只能接收到参加本次推演的agent产生的动作信息。</p> <p></p>

=== 关于单/多agent模式的说明 (reference/usage/#agent) ===

=== 单agent模式 (reference/usage/#agent_1) ===
<p>单agent模式指的是，一局游戏中，单方阵营内只有1个agent实例。此agent实例拥有操作本方阵营所有算子的权利。并且不会和其他agent发生信息交互。 此模式下的通常对抗场景有：</p> <ul> <li>1 × 人类队长 vs. 1 × agent</li> <li>1 × 人类队长 + i × 人类队员 vs. 1 × agent</li> </ul> <p>通常情况下0 &lt;= i &lt;= 4</p>
=== 多agent模式 (reference/usage/#agent_2) ===
<p>多agent模式指的是，在一局游戏中，任一方中有多个agent实例构成，比如一方阵营中1个队长，2个人类队员，和2个agent队员。 队长可以下达更多的动作，包括兵力编组，下达战斗任务等队长专属动作；而队员只可以下达一般动作。</p> <p>每个agent和人类只控制部分算子，并接收队长下达的任务。 在此模式下，agent实例之间存在潜在的信息上的交互。</p> <p>此模式的通常对战用例有：</p> <ul> <li>1 × 人类队长 + i × 人类队员 + j × agent vs. 1 × 人类队长 + m × 人类队员 + n × agent</li> </ul> <p>通常情况下0 &lt;= j, n &lt;= 5，0 &lt;= j+n &lt;= 5 </p>

=== 高程 (rules/elements/#_3) ===
<p>高程代表所在位置的相对地图中最低点的相对高度，在六角格上用颜色和数字标识，颜色越深高度越高，数字则对应具体的高程值。</p> <p>高程是陆战兵棋地形的重要属性，影响算子的机动、观察以及对火力打击产生影响：</p> <ul> <li>机动：相邻两六角格，高差越大，所需机动值越多，机动速度越慢；</li> <li>观察：地形的高低会产生对观察视野的遮挡，从而高地往往具有更开阔的视野，而低洼地带能够产生隐蔽的效果；</li> <li>射击：通常来说从高处打低处会取得更好的对敌毁伤效果，反之则削弱对敌的毁伤。</li> </ul>
=== 地物 (rules/elements/#_4) ===
<p>地物是某区域地表的包括特殊地形特征，包括：居民地，从林地，水域，松软地，公路、铁路等等</p> <p>地物特殊地形会对算子动作造成一定的影响，比如降低通行速度，改变被观察距离，降低打击效果等。 通常当车辆进入居民地、丛林地、松软地及水域机动速度将减缓，但当车辆是沿公路或铁路机动时，则不受高程、从林地、松软地等特殊地形对机动速度的影响； 车辆“行军”动作必须沿着公路线或铁路线才能实施（行军速度可达到普通机动速度的2倍）。</p>
=== 设施 (rules/elements/#_5) ===
<p>设施是为了达到对抗目的在某区域人工设置的条件，包括路障、间瞄炮火区、雷场等等</p> 雷场 发射阵地 通信节点 <ul> <li>路障：阻碍地面算子机动，地面算子（人员/车辆）无法通过设置有路障的区域。</li> <li>间瞄炮火区：为间瞄炮兵算子下达间瞄火力且炮火到达的区域。地面算子进出炮火区将受到间瞄火力裁决，详见间瞄射击规则和间瞄射击裁决表</li> <li>雷场：没有扫雷开辟通路功能的算子，也没有半速沿已开通路机动的算子，进入雷场后会受到雷场裁决，详见雷场裁决表</li> <li>发射阵地：发射车可以执行发射任务的地点</li> <li>通信节点：指挥车和通信车进行通信需要所处的位置</li> </ul>

=== 机动规则 (rules/rules/#_2) ===
<ol> <li>当棋子从一个六角格中心点机动至下一个相临六角格的中心点时，视为机动1格，以当前机动方式和下一个六角格的地形条件作为计算机动速度的依据。</li> <li>以棋子到达目标格的中心点作为后续机动或其他行动裁决的基准点，当棋子离开一个六角格的中心点后，在机动小于1格时射击或被射击等均以上一个六角格为裁决依据。</li> <li>机动指令一旦下达就不可更改，可以下达停止机动指令，停止机动指令下达后，当前机动指令未执行的部分不再执行，进入机动转停止阶段。</li> <li>机动状态有以下五种：正常机动，一级冲锋，二级冲锋，掩蔽，半速。以上状态之间互斥，算子在某一时刻只能处于一种状态之下。</li> </ol>
=== 机动停止 (rules/rules/#_3) ===
<ol> <li>地面棋子转换为停止状态需要75秒的“机动→停止”转换时间，空中棋子转为悬停状态需要75秒的“机动→悬停”转换时间。</li> <li>必须等待“机动→停止”转换完成后才能执行的命令有：车辆武器锁定、车辆武器展开、上下车、发射巡飞弹、步兵或战车直瞄/间瞄/引导射击、空中单位直瞄/间瞄/引导射击，等其他必须在静止状态下才能执行的动作。</li> <li>可以对机动中的棋子下达停止机动命令，收到停止机动命令后，棋子必须完成当前格的机动后，才能停止，棋子停止后即开始“机动→停止”转换。停止机动命令会导致75秒的惩罚性“机动→停止”转换，在这期间不能进行任何操作。</li> <li>地面算子在机动转停止过程中，可以进行改变机动状态（模式）的动作；包括切换至：正常机动，行军，一级冲锋，二级冲锋，掩蔽，半速；</li> </ol>
=== 车辆机动 (rules/rules/#_4) ===
<ol> <li>车辆在丛林地机动速度为正常速度的二分之一，居民地机动速度为正常速度的三分之一，小河流机动速度为正常速度的二分之一，大河流机动速度为正常速度的四分之一，松软地机动速度为正常速度的四分之一。</li> <li>地图的单位高程差表示六角格高度的最小变化值，一般分为5米，10米，20米</li> <li>地图的坡度等级是：两个六角格之间的高程差除以地图的单位高程差。一般分为1级坡度，2级坡度，3级坡度，4级坡度，5级坡度。1级坡度表示两个六角个之间的高程差等于1个单位高度差；2级坡度表示两个六角格之间的高程差等于2个单位高度差；3级坡度表示两个六角格之间的高度差等于3格单位高程差；依此类推。</li> <li>当车辆沿1级坡度地形机动时，按正常机动速度机动；当车辆在2级坡度地形机动时，按正常机动速度的1/2机动；当车辆在3级坡度地形机动时，按正常机动速度的1/3机动；依次类推；当坡度等级&gt;5时，车辆无法进入并通过。</li> <li>当车辆沿道路以机动状态行驶时，速度不受地形和高差的影响。</li> <li>炮兵不能机动</li> <li>路障地形不可通过</li> </ol>
=== 车辆行军 (rules/rules/#_5) ===
<ol> <li>车辆在行军方式速度为乡村路（黑色线）40千米/小时，一般公路（红色线）60千米/小时，等级公路（黄色线）90千米/小时。</li> <li>车辆必需进入道路六角格后才可转换为行军状态，转换过程需要75秒等待时间；只能沿道路走向规划行军路线，行军状态下速度不受地形和高差的影响。</li> <li>车辆行军前需要先将武器锁定（75秒时间）。</li> <li>如下一格存在停止的棋子或者非行军的棋子，则行军被阻挡</li> <li>行军状态下，棋子不能射击，不能引导射击，不能上下车，不能发射巡飞弹，不能离开道路。</li> <li>车辆由机动状态转为行军状态，或者由行军状态转为停止行军均需要75秒时间。</li> </ol>
=== 人员机动 (rules/rules/#_6) ===
<ol> <li>人员机动速度不受地形影响。</li> <li>当高差＞60米时，人员速度降为正常机动速度的一半。</li> <li>人员可以切换到一级冲锋状态或二级冲锋状态：<ol> <li>一级冲锋：人员速度提高为原来的2倍，每冲锋1格增加一级疲劳。</li> <li>二级冲锋：人员速度提高为原来的4倍，每冲锋1格增加一级疲劳。</li> <li>一级疲劳状态下不能实施二级冲锋，二级疲劳状态下不能机动。</li> <li>人员机动结束后，如果不继续机动，每75秒疲劳等级下降一级。</li> </ol> </li> <li>人员机动或冲锋过程中如果遭到压制，立即转为被压制状态，在完成当前格的机动后自动停止，直到秒后压制自动解除后才能继续执行未完成的机动或冲锋命令。</li> <li>人员转为冲锋状态后，只要不转为正常机动状态，就始终处于冲锋状态。</li> <li>路障地形可以通过</li> </ol>
=== 上下车规则 (rules/rules/#_7) ===
<ol> <li>上车单位与车辆位于同一格，且上车单位与车辆均处于停止状态，可执行上下车命令。</li> <li>上下车均需要75秒时间，在此过程中不可执行其它命令，也不可取消上下车命令。</li> <li>上车单位或车辆在开始上下车之前处于被压制状态下，不能开始上下车。</li> <li>如果已经处于上⻋状态，上车单位被压制会立即停⽌上⻋，⻋辆被压制会立即停⽌上⻋</li> <li>如果已经处于下⻋状态，⻋辆被压制会立即停⽌下⻋</li> </ol>
=== 掩蔽规则 (rules/rules/#_8) ===
<ol> <li>棋子转换为掩蔽状态需要75秒等待时间，在此过程中棋子不能执行其它命令。</li> <li>棋子在转换为掩蔽状态过程中，如果坦克射击会立刻中断掩蔽转换过程。</li> <li>棋子转为掩蔽状态后如果机动或射击则自动解除掩蔽状态，不需要消耗时间</li> <li>引导算子进行引导射击，不会退出掩蔽；被引导算子进行引导射击仍会解除掩蔽状态。</li> <li>如果先处于压制状态，棋子不可以执⾏掩蔽命令</li> <li>在转掩蔽过程中，棋子被压制会打断掩蔽命令</li> <li>先处于掩蔽状态中，棋子被压制不会结束掩蔽状态</li> <li>掩蔽，正常机动，一级冲锋，二级冲锋，半速状态之间互斥，算子在某一时刻只能处于一种状态下。</li> </ol>
=== 堆叠规则 (rules/rules/#_9) ===
<ol> <li>在同一个六角格内，不可堆叠超过4个本方地面单位。如果六角格内已存在4个本方地面单位，则格外本方地面单位不能再进入或通过该六角格。</li> </ol>
=== 夺控规则 (rules/rules/#_10) ===
<ol> <li>棋子只要机动（或行军）到夺控点中心，并且夺控点所在格及与其相临的6个六角格内无敌方地面单位，即可执行夺控命令。</li> <li>夺控无等待时间、也无需等待机动停止转换结束。</li> <li>空中单位和炮兵不能执行夺控命令。</li> <li>棋子在执行其它命令中和被压制时也可以夺控。</li> </ol>
=== 通视规则 (rules/rules/#_11) ===
<ol> <li>通视是判断两点之间是否有更高高程的遮挡物，以六角格为单位计算，使用六角格中心点到另一个六角格中心点之间连线判断是否通视。通视计算时，如果两个棋子高程不同，则遵循高看低原则，两个棋子高程高者为观察点，高程低者为目标点，位于高高程的棋子在所在六角格高程的基础上再加1个高程等级进行通视计算。</li> <li>通视计算时，连线高程定义为两个端点高程的线性插值，连线高程被更高高程的六角格（连线经过的居民地、丛林地六角格高程加1，两个端点所在六角格内的居民地、丛林地高程不被修正,但遵循高看低原则观察点的高程加1）所阻挡，则不通视。</li> <li>系统根据上述规则自动判断，通视的目标如果出现在观察单位的观察范围之内，会自动显示在态势中。根据上述规则，相邻六角格总是通视。</li> <li>手动判断方式：在交互界面上从六角格中心点到另一个六角格中心点之间连线，跳出的菜单中显示是否通视，连线间阻挡视线的更高高程六角格用红叉显示在界面上。</li> </ol>

<ol> <li>坦克主炮（大号、中号直瞄炮）具有行进间射击能力，可以在机动中射击。</li> <li>坦克在机动转停止、转掩蔽的过程中可以射击，转行军的过程中不能射击。</li> <li>无行进间射击能力的棋子转掩蔽、转行军的过程中均不能射击或引导射击。</li> <li>坦克由停止状态转换掩蔽状态的过程中可射击，射击后当前掩蔽命令取消。</li> </ol>
=== 武器冷却 (rules/rules/#_17) ===
<ol> <li>直瞄武器射击完毕后，需要75秒的冷却时间，冷却完成后才能继续射击。</li> <li>棋子武器冷却时，可同时执行机动、掩蔽等命令，武器冷却不受影响。</li> </ol>
=== 射击条件 (rules/rules/#_18) ===
<ol> <li>目标被射击者观察到且目标位于当前武器射程内。</li> <li>棋子武器已展开、射击过的武器已冷却结束。</li> <li>地面棋子处于停止状态（坦克主炮除外），空中棋子处于悬停状态。</li> </ol>
=== 战果表示 (rules/rules/#_19) ===
<ol> <li>战果为数字表示消灭了对方几个班（或几辆车），同时对车辆单位造成压制。</li> <li>无效，表示未对对方造成损失。</li> <li>压制，表示未消灭对方有生力量，但造成了对目标的压制。</li> </ol>
=== 直瞄射击战果修正 (rules/rules/#_20) ===
<ol> <li>射击单位处于机动中、被压制状态，战果作不利修正。</li> <li>目标单位处于掩蔽地形、机动中，战果作不利修正。</li> <li>目标单位处于堆叠状态、行军状态，战果作有利修正。</li> </ol>
=== 战果影响 (rules/rules/#_21) ===
<ol> <li>车辆被压制后人员不能上、下车，人员被压制后不能机动和射击。</li> <li>被压制的步兵棋子再次被裁决压制，损失1个班，剩余的班仍保持被压制状态。</li> <li>车辆棋子损失几辆车，车内步兵棋子也相应损失几个班。</li> <li>车辆被压制，车内人员不会被压制，但不能下车。</li> <li>压制状态持续秒后自动移除。</li> </ol>

=== 间瞄计划 (rules/rules/#_23) ===
<ol> <li>间瞄射击特指炮兵棋子的射击。</li> <li>间瞄射击需先进行间瞄计划，计划点标记后等待秒飞行阶段之后进行间瞄裁决，爆炸阶段持续秒，在此期间进入该格的棋子需受到一次间瞄裁决。</li> <li>间瞄计划的冷却时间为秒，</li> <li>正在飞行，未裁决的间瞄计划可以取消，间瞄计划的冷却时间清零</li> <li>间瞄冷却时间结束时可立刻进行下一次间瞄计划。</li> <li>由于计划的冷却时间为秒，而间瞄点存在时间最长为s+s，因此有可能出现同一炮兵同一时间具有2个间瞄点，一个在爆炸一个在飞行。</li> </ol>
=== 间瞄校射 (rules/rules/#_24) ===
<ol> <li>间瞄裁决时，如果有本方校射单位正在观察间瞄计划格或格内的目标，则裁决为有校射，否则按无校射裁决。</li> <li>校射单位包括本方所有地面单位和无人机，直升机和巡飞弹不能提供校射。</li> <li>校射观察的距离需遵守观察规则。</li> <li>无校射：间瞄裁决时本方没有单位能观察到目标格（不通视）。</li> <li>格内校射：间瞄裁决时本方有单位能观察到目标格，但观察不到格内目标（最远观察距离通视但不能观察）。</li> <li>目标校射：间瞄裁决时本方有单位能观察到目标格和格内目标（通视、能观察）。</li> </ol>
=== 间瞄裁决 (rules/rules/#_25) ===
<ol> <li>间瞄裁决后，会对经过爆炸区域的棋子产生持续性伤害，持续时间为秒。</li> <li>如果在裁决的秒之间炮兵机动，则立刻取消间瞄裁决点</li> <li>间瞄裁决不仅对敌方，对已方也会造成伤害。</li> <li>命中：表示炮火准确命中目标格及格内目标。</li> <li>散布：表示炮火命中目标格，但没有命中格内目标。</li> <li>散布n格：表示炮火实际命中格距离计划格n格。</li> </ol>
=== 间瞄射击战果修正 (rules/rules/#_26) ===
<ol> <li>目标单位处于掩蔽地形、掩蔽状态、未机动，裁决结果作有利于目标单位的修正。</li> <li>目标单位处于堆叠状态、机动或行军状态，裁决结果作不利于目标单位的修正。</li> </ol>
=== 巡飞弹规则 (rules/rules/#_27) ===
<ol> <li>巡飞弹飞行速度为8秒/格，飞行高度为所在格高程基础上增加200米。</li> <li>巡飞弹对暴露的地面目标的侦察距离为2格，按照通视规则对目标进行侦察，车辆目标处于掩蔽状态，巡飞弹对其侦察距离不受影响，人员目标处于掩蔽状态，巡飞弹对其侦察距离减半。</li> <li>巡飞弹棋子由所属车辆发射，对抗开始后才能发射巡飞弹。</li> <li>巡飞弹部署及发射均需75秒时间，战车棋子一次只能发射一枚巡飞弹。</li> <li>巡飞弹飞行过程中，发射车可以正常行动，包括机动与射击，但不能发射其它巡飞弹。</li> <li>巡飞弹发现打击目标后马上可以进行打击，无需飞完全部机动路线。</li> <li>巡飞弹的巡飞时长为0秒，超时则自毁。发射后的巡飞弹如遇发射车被摧毁，则巡飞弹自毁。</li> <li>如果巡飞弹的所属车辆被击毁，巡飞弹也会被击毁</li> </ol>
=== 无人机规则 (rules/rules/#_28) ===
<ol> <li>无人机飞行速度为8秒/格，飞行高度为所在格高程基础上增加200米。</li> <li>无人机对暴露的地面目标的侦察距离为2格，按照通视规则对目标进行侦察，车辆目标处于掩蔽状态，无人机对其侦察距离不受影响，人员目标处于掩蔽状态，无人机对其侦察距离减半。地面单位对无人机的观察距离为相邻格。</li> </ol>
=== 武装直升机规则 (rules/rules/#_29) ===
<ol> <li>直升机飞行速度为4秒/格，飞行高度为所在格高程基础上增加200米。</li> <li>武装直升机对暴露的人员目标的观察距离为10格，对暴露的车辆目标的观察距离为25格，按照通视规则对目标进行侦察，车辆目标处于掩蔽状态，武装直升机对其侦察距离不受影响，人员目标处于掩蔽状态，武装直升机对其侦察距离减半。</li> <li>武装直升机对无人机、巡飞弹的观察距离为当前格和相临格，地面单位对武装直升机的观察距离为25格，武装直升机相互间的观察距离为25格。</li> </ol>
=== 无人战车规则 (rules/rules/#_30) ===
<ol> <li>无人战车棋子的机动、侦察、直瞄射击规则同战车规则。</li> <li>无人战车需依托有人战车为载体，无人站车必须与一辆有人战车有隶属关系</li> <li>无人战车下车后，在停止状态下可在具备引导射击条件时，引导所属有人战车进行射击。</li> <li>无人战车所属有人战车如被摧毁，则无人战车一同被歼灭</li> </ol>
=== 引导射击规则 (rules/rules/#_31) ===
<ol> <li>引导射击可由步兵，无人战车、无人机实施。引导射击条件：<ol> <li>引导算子必须观察到拟攻击目标</li> <li>拟攻击目标在被引导算子（重型战车）的可被引导武器的射程范围内（可不通视）</li> </ol> </li> <li>步兵，无人战车只能对所隶属车辆的重型导弹进行引导，无人机可对本方所有装备了重型导弹的车辆单位进行引导，无人机一次只能引导一个单位进行射击。</li> <li>战车被引导射击时，自身需处于武器已展开、武器已冷却、未机动、未正在执行其它命令状态。</li> <li>步兵，无人车在机动状态、被压制状态、正在执行其它命令状态、武器未展开、未冷却结束等状态下不能引导射击。无人机必须在悬停状态下才可以引导射击。</li> <li>只有战车的重型导弹支持被引导射击，其它武器均不支持被引导射击。</li> <li>实施引导射击后，引导算子和被引导算子，均需要75秒的准备时间才能再次进行引导或使用自带的武器进行直瞄射击。</li> </ol>
=== 同格交战规则 (rules/rules/#_32) ===
<ol> <li>当同一六角格内存在双方地面算子时，触发同格交战规则，格内地面算子处于同格交战状态，自动按距离为0格进行直瞄射击裁决；将自动选择攻击等级最高的武器进行打击，裁决顺序按照先进入该六角格的算子先实施打击；其打击目标的选择按照“坦克”&gt;“战车”&gt;“其他车辆”&gt;“人员”的优先顺序自动选择；当存在同类型多个目标时，优先选择班组数少的算子进行打击（同类目标班组数相同则随机选择）。</li> <li>同格交战会每间隔25秒自动进行一次直瞄射击；进入同格交战状态的第一瞬间会立刻进行一次直瞄射击切不受武器冷却时间、机动状态和压制状态的限制，但武器未展开的算子（行军中）、未下车的人员不得实施射击。在进入同格交战状态前存在的武器冷却状态会取消，被同格交战的直瞄射击造成的冷却状态替代</li> <li>当同格交战发生时，处于格外的算子不能对处于同格交战状态的算子进行直瞄射击；处于同格交战状态的算子依然会受到间瞄火力的打击。</li> <li>处于同格交战状态的算子只能接受机动指令，用于脱离同格状态，但是下达机动会受到处于同一格内的所有敌方算子的一次惩罚性打击；</li> <li>同格交战状态会中断“上下车”，“转隐蔽”，“武器展开和锁定”的转换过程，但不会影响算子已经进入的状态如：机动、行军、掩蔽、压制、堆叠等。</li> <li>同格交战状态的解除：当前无敌我双方算子处于同六角格格。可能的情况包含：处于同格交战状态的一方算子机动离开同格交战所在六角格；或同格中的一方算子被全部歼灭。同格交战状态解除时，正在进行中的武器冷却状态会继续存在，直到正常倒计时结束。</li> <li>在使用步兵轻武器对车辆单位实施打击时，攻击等级见《步兵轻武器对车辆攻击等级表》，战斗结果见《直瞄武器对人员/步兵轻武器对车辆战斗结果表》，战果修正见《车辆战损结果修正》。</li> </ol>
=== 运输直升机规则 (rules/rules/#_33) ===
<ol> <li>直升机飞行速度为4秒/格，滞空状态分为高空”、“低空”、“超低空”三种空中状态</li> <li>三种状态分别按照所在六角格的高程上增加500米、200米、20米计算通视，不同高度状态下射击战果和遭受打击战损修正不同</li> <li>超低空状态下机动速度减半</li> <li>直升机可通过“切换高度”指令实现在相邻的两个高度状态之间切换，切换高度消耗时间75秒。</li> <li>步兵单位可乘坐运输直升机快速机动。直升机以悬空索降“装载”和“卸载”人员单位，装卸载过程消耗75秒时间。装载与卸载必须在开阔地实施；直升机处于“超低空”状态；人员与直升机均为“停止”、非“压制”等（同上下车）</li> <li>搭载的步兵单位班数需小于或等于直升机的承载单位数，如步兵班数大于承载单位数，可通过“解聚”操作，实现分组降班，再行搭乘；运输直升机“装载”时必须处于“空载”状态（即机上无人员单位，如装载有人员单位，需先将人员卸载，再将人员编组后执行装载）</li> <li>运输直升机同时只能执行“装载”或“卸载”一种动作；装卸载过程中不能执行射击、掩蔽、机动等其他动作。</li> <li>直升机在处于超低空状态，装卸载时及飞行过程中可遭受炮兵火力打击，并作为整体接受毁伤裁决。出现战损，直升机和装载单位同等损失；直升机装卸载过程中遭受直瞄或间瞄射击被压制，装卸载失败，须等待压制效果移除后重新装卸载。</li> </ol>
=== 聚合解聚规则 (rules/rules/#_34) ===
<ol> <li>为便于推演人员灵活使用兵力，增加地面算子“聚合”、“解聚”规则，允许推演人员对算子进行聚合（整编兵力）解聚（区分兵力）操作。</li> <li>处于相同六角格内的两个（只能两个算子之间聚合，可通过多轮聚合实现三个及以上算子的兵力整编）同类型算子可进行“聚合”操作。聚合的算子须处于静止、未射击等行动状态（包括乘车、乘机、被压制等），且聚合后的总班数不得大于4。下达聚合指令后，经过75秒，算子完成聚合，生成一个新算子（车班数为累加值）。</li> <li>算子解聚时，该算子必须处于静止、未射击等行动状态（包括上下车、被压制等）。下达解聚指令后，经过75秒完成解聚，由算子生成两个新算子，解聚模式为：+=，+1。</li> <li>在聚合解聚过程中，执行操作的算子遭受射击被压制、进入同格交战状态等，聚合解聚失败。正在聚合与解聚过程中的算子不可执行射击、机动、掩蔽、夺控等操作。</li> <li>战车发射巡飞弹后，巡飞弹在空中存活时，该战车不可进行聚合解聚动作。</li> <li>战车上有搭载乘员时，乘员和战车分别进行聚合解聚。动作结束之后分别根据规则确定乘员和战车的车班数，并原有保持状态。</li> <li>解聚后，两个生成的算子的弹药数与原算子保持不变。聚合之后，合成的算子的弹药数按照两个算子的弹药数的平均数向下取整。其他算子属性，除车班数外，均保持不变</li> <li>战前部署阶段允许地面算子执行聚合解聚。</li> <li>炮兵暂不支持聚合解聚</li> </ol>
=== 特别防空算子规则 (rules/rules/#_35) ===

=== 侦察与校射规则 (rules/rules/#_36) ===
<ol> <li>增加专业侦察力量和装备。</li> <li>“侦察型战车”，对地面单位侦察距离最大为50格，</li> <li>“炮兵校射雷达”，属车辆单位。开机工作后，已方炮火统一按照格内校射进行散布裁决。</li> <li>雷达车处于静止、未被压制状态下，可下达“开启雷达”指令，经75秒后雷达车处于开机状态。雷达在开机过程中遭直瞄或间瞄射击产生压制战果时开机过程中断。</li> <li>雷达开机工作期间可以执行“机动”指令，下达机动指令后，开机状态立即停止，尔后按机动规则实施机动。需通过“开启雷达”指令重新经75秒重新进入雷达开启状态。</li> <li>当雷达车处于雷达开启状态时被裁决压制，雷达开启效果失效，压制状态结束后雷达开启效果自动恢复，无需再次下达指令重复开启雷达。</li> </ol>
=== 工事规则 (rules/rules/#_37) ===
<ol> <li>现有工事类型为永久性工事。</li> <li>工事的基本作用是为进入工事的人员或车辆提供隐蔽和防护。</li> <li>工事区分为人员工事（战斗工事，隐蔽工事）和车辆工事两类，人员和车辆单位只能进入相应类型的工事（载人车辆按车辆处理，进入车辆工事。</li> <li>每个六角格只能设定一个工事，每个工事可容纳的人/车班数为5。</li> <li>当裁决结果导致工事内的人员或车辆车班数大于工事剩余容量时，工事内部所有单位瞬时退出工事，视同人员或车辆失去工事保护，按暴露状态进行观察和被射击裁决。</li> </ol>
=== 车辆工事 (rules/rules/#_38) ===
<ol> <li>工事本身具有一定的隐蔽效果，双方算子只可对12格内的对方工事进行观察和直瞄间瞄射击。工事所在六角格，如处于居民地、丛林地等，其地形属性对工事在被观察、被射击时的影响同样存在，需进行相应修正。</li> <li>车辆进入相应工事所在格时，推演人员下达“进入工事”指令，等待75秒完成进入。如进入工事的车辆车班数大于工事剩余容量，进入失败。进入工事的单位不可被观察（全程隐蔽），但可进行直瞄射击（包括对地、对空射击）。下达“离开工事”指令，等待75秒车辆离开工事，停留在工事当前格，可被观察。</li> <li>处于被观察范围内的工事可被直瞄和间瞄射击，射击结果按对车辆射击结果进行裁决，并按结果裁定剩余工事容量。</li> <li>工事的防护可设定为重型（野战工事）、中型（简易工事）两类，遭射击时可进行射击结果修正。</li> <li>工事遭射击时，如内部为车辆单位，车辆不继承射击结果</li> <li>当裁决结果导致工事内的车辆车班数大于工事剩余容量时，工事内部所有单位瞬时退出工事，视同车辆失去工事保护，按暴露状态进行观察和被射击裁决。</li> </ol>
=== 人员战斗工事 (rules/rules/#_39) ===
<ol> <li>工事本身具有一定的隐蔽效果，双方算子只可对12格内的对方工事进行观察和直瞄间瞄射击。工事所在六角格，如处于居民地、丛林地等，其地形属性对工事在被观察、被射击时的影响同样存在，需进行相应修正。</li> <li>人员进入相应工事所在格时，推演人员下达“进入工事”指令，等待75秒完成进入。如进入工事的人员车班数大于工事剩余容量，进入失败。进入工事的单位不可被观察（全程隐蔽），但可进行直瞄射击（包括对地、对空射击）。下达“离开工事”指令，等待75秒人员单位离开工事，停留在工事当前格，可被观察。</li> <li>处于被观察范围内的工事可被直瞄和间瞄射击，射击结果按对车辆射击结果进行裁决，并按结果裁定剩余工事容量。</li> <li>工事的防护可设定为重型（野战工事）、中型（简易工事）两类，遭射击时可进行射击结果修正。</li> <li>工事遭射击时，如内部为人员单位，人员直接继承射击结果。</li> <li>当裁决结果导致工事内的人员班数大于工事剩余容量时，工事内部所有单位瞬时退出工事，视同人员失去工事保护，按暴露状态进行观察和被射击裁决。</li> </ol>
=== 人员隐蔽工事 (rules/rules/#_40) ===
<ol> <li>工事本身具有一定的隐蔽效果，双方算子只可对本格内的对方工事进行观察，工事不受所在六角格地形属性影响。</li> <li>人员进入相应工事所在格时，推演人员下达“进入工事”指令，等待75秒完成进入。如进入工事的人员车班数大于工事剩余容量，进入失败。进入工事的单位不可被观察（全程隐蔽），也不能进行直瞄射击（包括对地、对空射击）。下达“离开工事”指令，等待75秒人员单位离开工事，停留在工事当前格，可被观察。</li> <li>处于被观察范围内的工事不能被直瞄和间瞄射击。</li> <li>工事所在格里有敌方单位进入，守方立即暴露，自动离开工事，同时发起同格交战，先裁决守方；</li> <li>工事中无守方单位，不影响敌方单位夺取控制点</li> </ol>
=== 推演规则 (rules/rules/#_41) ===

=== 雷场规则 (rules/rules/#_42) ===
<ol> <li>增加防步兵坦克混合雷场，主要以临时抛撒布设，雷场观察距离为10格，遮蔽地形对雷场观察减半。</li> <li>允许在想定设计中预先设定雷场，在推演过程中，推演人员可使用“火箭布雷车”布设雷场。</li> <li>“火箭布雷车”可在50格内进行“布雷”作业，下达“布雷”指令后75秒完成1个雷场六角格的布设，一辆车最多可进行3次布雷。</li> <li>火箭布雷车布雷时，必须处于静止、未被压制状态下，在布雷75秒期间雷车机动或被压制，布雷均失败。</li> <li>雷场对敌我双方均有效，未开辟雷场通路进入雷场六角格，须进行毁伤裁决。</li> <li>推演人员可使用“扫雷车”或“坦克”，以半速通过雷场六角格，完成雷场通路开辟。</li> <li>雷场通路具有进出雷场的方向，同道路。</li> <li>一方开辟的雷场通路只能被己方可见并使用；</li> <li>人员单位沿雷场通路通过雷场或车辆单位以半速沿雷场通路通过雷场不进行雷场毁伤裁决。</li> <li>雷场裁决表见附录</li> </ol>
=== 支援算子规则 (rules/rules/#_43) ===

=== 天基侦察算子 (rules/rules/#_44) ===
<ol> <li>天基侦察算子主要有侦察敌方兵力的作用。</li> <li>算子不设分值，不可机动，不可攻击与被攻击。</li> <li>当本方有天基侦察算子时，可侦察到敌方所有不在工事内的算子，不可见车班数，弹药数，战损状态；每个六角格内只显示编号最小的一个算子；</li> <li>天基算子的观察到的算子不等于被算子直接观察到，不可直接发动直瞄打击。</li> <li>天基算子无需激活。</li> </ol>
=== 电子干扰规则 (rules/rules/#_45) ===

=== 全局电子干扰 (rules/rules/#_46) ===
<p>队长可以下达全局干扰指令，使得敌方的所有具备引导射击能力的算子（通常是无人机，无人车，步兵）暂时失去能力。</p> <p>该效果一般持续75步，且在600步后可以再次实施全局干扰。</p> <p>全局电子干扰可以影响一号车与营车之间的通信。</p>
=== 局部电子干扰 (rules/rules/#_47) ===
<p>局部电子干扰指的是电子干扰车或电子干扰小队对特定范围内实施电子干扰。</p> <p>在电子干扰的作用范围内，敌方的无人单位（通常是无人车，无人机）无法接收到新的指令，但是正在执行的任务可继续执行（例如在干扰之前下达的机动动作）。</p> <p>局部电子干扰需声明干扰的方向，随后干扰范围为该方向展开120°的扇形，对于干扰车延展距离为25格，对于干扰小队延展距离为5格。</p> <p>电子干扰开启后最大持续75步，电子干扰的冷却时间为150步</p> <p>实施干扰单位如果被摧毁，实施机动，或出现其他打断其干扰行动的事件，中断干扰状态，对敌方单位的干扰影响将立刻消失。</p> <p>局部电子干扰可以影响一号车与营车之间的通信。</p>
=== 场外火力支援 (rules/rules/#_48) ===
<p>场外火力支援相关规则模拟了场外因素对战场内的各类影响。 此类规则不涉及相关算子，以独立动作的形式存在于对抗中。 火力支援有资源限制，主要以使用次数的形式体现，且同阵营内共享资源。 火力支援相关动作不限制推演人员的权限，队长队员均可下达。</p>
=== X火力支援 (rules/rules/#x) ===
<p>模拟重型炮对场内进行的目标校射间瞄火力打击。 一次推演内可使用12次。 选择火力打击点并下达指令后，火力将于100步之后到达，不可取消，对己方同样造成伤害。 火力在飞行过程中对敌方不可见，对己方可见。 火力到达后持续100步。</p>
=== Y火力支援 (rules/rules/#y) ===
<p>模拟重型炮对场内进行的无校射间瞄火力打击。 一次推演内可使用12次。 选择火力打击点并下达指令后，火力将于100步之后到达，不可取消，对己方同样造成伤害。 火力在飞行过程中对敌方不可见，对己方可见。 火力到达后持续100步。</p>
=== 卫星支援规则 (rules/rules/#_49) ===
<p>卫星支援规则模拟卫星的临空侦察支援，其效果是：</p> <ul> <li>侦察到敌方所有不在工事内的算子，不可见车班数，弹药数，战损状态</li> <li>每个六角格内只显示编号最小的一个算子；</li> <li>观察到的算子不等于被己方算子直接观察到，不可直接发动直瞄打击。</li> </ul> <p>卫星凌空作为动作，作为阵营的共享资源，可被同一阵营的任一推演者实施，并共享其效果和冷却时间。</p> <p>卫星凌空动作有以下时间参数，可通过对环境初始化配置改变：</p> <ul> <li>效果延迟步长：指的是下达动作后，多长时间才可以得到卫星凌空的支援效果，默认值450步</li> <li>效果持续时间：指的是卫星凌空支援效果的持续时间，默认值150步</li> <li>动作冷却时间：指的是两次卫星凌空之间需要等待的冷却时间，默认值600步</li> </ul> <p>当己方发起卫星侦查请求时，如果敌方如果配置了保障车，敌方将获得通知。</p>

=== 系统概述 (tutorials/basic/#_2) ===
<p>本平台是是一个实时制的战术级陆军兵棋人机智能博弈平台，是一种人在回路的复杂策略对抗游戏，对为人工智能技术研究提供了一类复杂不完美信息博弈问题环境。本平台基于人工智能前沿理论重构了传统计算机兵棋系统——通过对推演环境、内存训练接口、网络对抗接口的封装，为AI研发提供了超高速单机训练与调试环境（普通PC上分队级内存推演只需要数秒时间）；同时提供开放性的AI接入，符合接口规范的AI均可接入平台，在网络上开展机机、人机和人机混合对抗。 本文档主要面向使用本平台进行兵棋推演的人类用户，阐述系统的使用。</p> <p>Note</p> <p>建议使用Chrome 80版本及以上版本浏览器。</p>
=== 使用说明 (tutorials/basic/#_3) ===

=== 进入兵棋对抗 (tutorials/basic/#_4) ===
<p>注册并登录系统的正式用户，可通过“对抗系统-&gt;进入对抗”开启在线兵棋对抗。目前系统分为分队级对抗（1V1对抗）和群队级对抗（nVn对抗，比赛常使用3V3和5V5）两种规模，支持：人人对抗、人机对抗，以及群队级对抗的人机混合对抗三种模式。用户可以通过“房间匹配码”、“选择公开房间”和“创建房间”三种方式进入推演。</p> <ul> <li>使用房间匹配码：在上方输入框中输入房间匹配码，点击“进入房间”按钮，可直接进入对应的房间开始对抗。此模式适用于人人选手之间约战，一个人创建好房间后，将房间匹配码发送给约战对手，快速进入对抗。</li> <li>选择公开房间：点击“公开房间”按钮，可查看当前其他选手建立、可进入的房间，开展对抗。</li> <li>创建房间：用户也可以新建一个属于自己的房间来开展推演。</li> </ul> 输入房间匹配码直接进入房间

=== 兵力编组 (tutorials/basic/#_11) ===
<p>分队级对抗无编组阶段，将直接跳过本阶段进入“部署”的阶段。 群队级对抗中，营长席位具有“编组”权限，营长在本阶段通过“编组”指令将算子分配给相应的队友控制（在推演过程中，营长也可通过“编组”指令，转移算子的控制权，调配兵力）。</p> <p>编组方法：在左侧“兵力编成”界面，通过复选框选中想要进行控制权调整的算子，右键菜单将选中的算子指派给对应的选手（包括AI），编组成功后右侧会显示编组成功弹出框。</p> 营长席位进行编组
=== 编组完成 (tutorials/basic/#_12) ===
<p>营长席位完成编组指派后，需点击右上方菜单栏中“完成”按钮，结束编组阶段，进入“部署”阶段。</p>
=== 战前部署 (tutorials/basic/#_13) ===
<p>战前部署阶段允许推演人员操作由自己控制的算子，进行上下车部署（将于本阶段瞬间完成，不占用推演时间），同时也允许推演人员对自己控制的算子下达规划指令，规划指令将在推演计时开始后被逐步执行。 战前部署阶段操作右下方指令区。</p>
=== 推演开始 (tutorials/basic/#_14) ===
<p>对抗双方的所有选手点击部署“完成”按钮后，或是编组与部署时长到达120秒时，推演将自动开始。</p>

=== 实时指令与计划指令 (tutorials/basic/#_17) ===
<p>系统提供了“实时”与“计划”两种指令下达，在战术级兵器中，两种指令内容一致，其差异在于： 计划指令有推演人员提前下达，进入指令队列，按队列排序逐一执行； 实时指令则为下达后立即执行的指令。 推演人员可根据需要和操作习惯，自由使用两种指令模式。</p>
=== 算子进行机动 (tutorials/basic/#_18) ===

=== 引导射击 (tutorials/basic/#_21) ===
<p>实时指令区信息框中，如当前有算子可以实施引导射击，则会显示出“引导”按钮，点击“引导”按钮后，鼠标单击选择打击算子，弹出选择引导算子确认框，可进行选择引导算子，单击确认后下达引导指令。打击完毕会显示损伤和状态信息。 步兵、无人战车、无人机算子都可以引导射击，只可以引导携带导弹武器的算子。引导射击需要附近有可以被引导的算子以及敌方算子在被引导射击的算子攻击范围内。</p> 引导射击指令与选择引导算子框
=== 上下车 (tutorials/basic/#_22) ===

=== 掩蔽 (tutorials/basic/#_23) ===
<p>单击算子，在指令区中点击“掩蔽”按钮，算子即开始从正常状态转换成掩蔽状态，转换成功后，算子图标下方会显示“掩蔽”标记。下达其他移动的指令后移除掩蔽状态。</p>

=== 网络推演与内存推演的差异 (tutorials/upload/#_1) ===
<p>在单机训练版中，推演裁决引擎由run_offline_games.py推动。对抗推演的推进过程中，红蓝双方AI的决策与裁决是顺序串联的：在每一步中，环境会都等待双方决策，当红蓝都完成决策后，环境根据接收到的动作进行裁决向前推进。该设计是为了：</p> <ol> <li>按step推进，方便强化学习AI开展训练</li> <li>串联的执行方式支持AI调试过程中设置中断</li> </ol> <p>但在网络对抗过程中，一场对抗的对局时长由加速比来确定，红蓝agent和裁决引擎是分布的3个独立进程，裁决引擎按照加速时钟独立推进，不会等待AI决策的动作，而是持续轮询，什么时候收到AI发来的动作，就什么时候裁决该动作。</p> <p>举例来说：假设加速比为5，即裁决引擎的推进间隔为200ms。那么如果agent的决策时间加上态势与动作收发的网络延时在200ms以内，那么AI就能在每一帧都拿到态势进行决策，此时和单机训练版几乎无差别（如下图左图所示）。但如果计算时间长，超过了200ms，则和单机训练版相比会有两个区别：</p> <ol> <li>这次“缓慢”决策所生成的动作，到达裁决可能已经“过时”而裁决为“无效”</li> <li>在这次“缓慢”决策过程中，环境定时发出的逐帧态势到达，但agent正在决策计算中而消息被阻塞，当agent完成决策发出动作后，只会看到发出动作后再到达的新的态势，中间态势则看不到了（即“丢帧”）</li> </ol> <p>如下图所示，由于a<sub>0</sub>动作决策时间长，s<sub>1</sub>和s<sub>2</sub>两帧态势agent无法获得。</p> <p></p>
