# 专家战术合理性评分协议（`P3` 步骤 4 / `I17`；31007 6.2.3）

> **本文件是"评分协议"**：规定**维度、流程、样本量、一致性要求**。
> 对应实现：`training/expert_rating.py`；对应测试：`tests/test_p3_expert_rating.py`。
> **⚠ 本文的维度、权重与阈值均为本项目自定** —— 31007 6.2.3 **只规定"专家 0-10 分"**，
> 未规定维度划分、权重、评分者人数与一致性阈值。**报告中引用时必须注明这一点。**

---

## 1. 量程与维度

### 1.1 量程

**每一维度 0—10 分**（整数或半分）。标准只给出总分范围，本项目**把总分拆成维度分**，
理由：单一总分无法区分"打得准但不合规"与"合规但打偏"，而二者在**合规维度**上的处置完全不同。

| 取值 | 含义 |
| --- | --- |
| 0 | 完全不符合该维度要求 |
| 5 | 中性 / 无明显优劣 |
| 10 | 该维度上无可指摘 |

**越界分（<0 或 >10）不被截断，而是被拒绝并单列**（`dimensions_invalid`）——
截断会把"打错了"静默变成"打了个边界值"。

### 1.2 五维度与权重（**本项目自定**）

| 维度 | 含义 | 权重 |
| --- | --- | --- |
| `mission_fit` | **任务契合**：动作是否服务于当前任务目标 | 0.30 |
| `timing` | **时机**：是否在恰当的态势窗口内行动 | 0.20 |
| `resource_use` | **资源运用**：弹药 / 油料 / 兵力消耗是否合理 | 0.15 |
| `risk_control` | **风险控制**：是否避免不必要的暴露与损失 | 0.15 |
| `legality` | **规则合规**：是否违反交战规则或约束 | 0.20 |

**`legality` 为"否决性"维度**，故给它较高的 0.20：

> 一个动作即使任务契合度满分，**若违规，其战术合理性仍应被显著压低**。
> 但本项目**不把它做成硬性一票否决** —— 否决与否是**指挥决策**，不是评分协议该替用户做的判断。

### 1.3 总量计算

```
总分 = Σ(权重_i · 维度分_i) / Σ(权重_i)      ← 仅对**可得分**维度求和
```

**关键：缺失维度退出分母。** 若某评分者漏打一维，该维不参与该样本的总分，
**而不是按 0 计入** —— 否则"没评"会被当成"评了低分"。

## 2. 评分流程

| 步 | 动作 | 产出 |
| --- | --- | --- |
| 1 | **选取样本**：从 `Shenji/configs/eval_cases_intensity_v1.json` 按档抽取 | 样本 ID 清单 |
| 2 | **盲评**：评分者**不看模型名/档位标签**，只看动作与态势 | 每样本原始分 |
| 3 | **独立打分**：每位评分者独立完成，**不得商议** | 每评分者一份 `{样本: {维度: 分}}` |
| 4 | **计算一致性** | `ICC(2,1)`（见 §4） |
| 5 | **分歧复核**：对 `spread` 大的样本组织复核（**复核结论需记录**） | 复核记录 |
| 6 | **汇总** | `aggregate_expert_scores()` 输出 |

**样本形状**（与实现一致）：

```python
ratings_by_rater = {
    "expert_1": {"<样本ID>": {"mission_fit": 8, "timing": 7, ...}},
    "expert_2": {...},
}
```

## 3. 样本量要求

| 项 | 要求 | 依据 |
| --- | --- | --- |
| 评分者 | **≥ 2 人**（`ICC` 的数学下限）；**建议 3 人** | `ICC(2,1)` 需 k≥2 |
| 样本 | **≥ 2 个**（目标间方差下限）；**建议 ≥ 20 个** | 同上 |
| 每档覆盖 | **三档各 ≥ 1 个样本**；**建议各 ≥ 5** | 与 `I16` 的强度分档对齐 |

**⚠ 未达下限时不报错，而是如实返回 `icc=None` + 理由** —— 见 §4.3。

## 4. 一致性要求

### 4.1 为什么用 **ICC(2,1)** 而不是 Cohen's κ

| | κ | **ICC(2,1)** |
| --- | --- | --- |
| 适用数据 | **分类**评分 | **连续 / 有序**评分 |
| 对 0-10 分 | 需先**分箱** → **丢信息**，且阈值解释随之改变 | 直接使用数值 |

本量表是 **0-10 有序/连续**，故用 `ICC(2,1)`（**双向随机效应、绝对一致性、单次测量**）。

**"绝对一致性"的含义**：若甲始终比乙高 2 分，**ICC 应当下降** ——
因为本协议要的是"打出的分数可互换"，而"相关性高但系统性偏移"不满足这一点。
（实现中有一条测试专门钉住该口径。）

### 4.2 所用公式（报告中必须回带）

```
ICC(2,1) = (MSR − MSE) / ( MSR + (k−1)·MSE + k·(MSC − MSE)/n )
```

其中 `MSR`=目标间均方、`MSC`=评分者间均方、`MSE`=残差均方，`n`=目标数、`k`=评分者数。

### 4.3 **本项目不给"合格/不合格"判定**

> 「0.75 以上为良好」**是惯例，不是 31007 的规定**（标准未给阈值）。

故实现**只回带 ICC 数值、公式与各均方**，**由报告作者结合用途解释**。
这样做的理由是：把惯例写成"标准要求"会让后续复核无法区分二者。

### 4.4 ★ 同时报告 **Kendall' + chr(39) + 's W**（I17 步骤 1 点名的系数）

I17 步骤 1 原文写「一致性系数（**如 Kendall W**）」。
本项目**同时报告 W 与 ICC**，因为**两者回答不同问题**：

| 系数 | 问的问题 | 数据要求 |
| --- | --- | --- |
| **Kendall' + chr(39) + 's W** | 评分者对**对象排序**是否一致？ | 排序 / 可转秩的分数 |
| **ICC(2,1)** | 同一对象上评分者的**绝对分**是否可互换？ | 每个对象的绝对分 |

**实测差别（本项目合成数据，可复算）**：

| | 原始 | 第二位评分者**一律 +3 分**后 |
| --- | --- | --- |
| **Kendall' + chr(39) + 's W** | **1.000000** | **1.000000**（**不变**） |
| **ICC(2,1)** | **0.636364** | **0.218750**（**下降**） |

**即**：整体平移不改变排序（W 不变），但破坏"分数可互换"（ICC 下降）。

> **报告须写明采用哪个口径**。本项目建议：**判断"评分者排序是否一致"用 W；
> 判断"分数能否互换"用 ICC** —— 二者不可互相替代。

实现见 	raining/kendall_w.py（含并列修正），测试见 	ests/test_i17_kendall_w.py。

### 4.5 缺分处理

| 情形 | 处置 |
| --- | --- |
| 某评分者漏打某**维度** | 该维**退出该样本的总分分母** |
| 某评分者漏评某**样本** | 该样本**退出 ICC**，并登记 `excluded_from_icc` 及理由 |
| **任何情形** | **不得用均值填补** —— 填补会**人为抬高一致性** |

## 5. 规则冲突检测

`P3` 步骤 4 要求"专家 0-10 分 + **规则冲突检测**"。实现见 `rule_conflicts()`。

| 规则 | 冲突对 |
| --- | --- |
| `occupy_vs_withdraw` | 同一 `actor` 在同一 `target` 上"占领"与"撤离" |
| `attack_vs_hold_fire` | 同主体同目标"打击"与"停火" |
| `engage_vs_disengage` | 同主体"交战"与"脱离" |

**两条边界（重要，避免误报）**：

| 情形 | 判定 |
| --- | --- |
| **不同主体**做相反动作 | **不是冲突** —— 那是正常对抗 |
| 同一主体**不同目标** | **不是冲突** |

**冲突只报告双方索引，不自动判定谁错** —— 判定依赖态势，属指挥判断。

## 6. 与其它模块的关系

| 模块 | 关系 |
| --- | --- |
| `training/alignment.py` | **认知对齐度**（31007 6.2.4）—— 与本协议**并列**，不是同一指标 |
