# 庙算陆战引擎（land_wargame_train_env 4.1.0）装备与裁决数据字典

> 来源：`train_env/Data/weapons/`（引擎 wheel 内置，随包分发）
> 用途：作为自研三维战役引擎复现陆战裁决语义、并扩展海空算子时的**唯一权威数据基准**。
> 采集日期：2026-09-15

## 0. 结论摘要

- 引擎内核为**纯闭源二进制**（178 条目 / 125 个 `.so` / 仅 1 个 `.py`），**不可修改**。
- 但**裁决语义可从数据文件完整还原**：共 19 个数据文件，含完整的攻击力表、射程表、2d6 裁决表（CRT）、高程修正表、直瞄/间瞄偏移表。
- 数据文件总量仅 288 KB，全部为可读的 Excel / CSV / 纯文本矩阵。
- **复现风险已从"高"降为"中"**：语义可得，缺的是算子状态机与推演流程逻辑（需从观测/动作接口反推）。

## 2. 主武器表 `WpData.xls` / `WpData.csv`（81 行 × 62 列）

两文件内容一致（CSV 为 XLS 的文本导出）。

### 列定义

| 列 | 字段 | 含义 |
|---|---|---|
| 0 | `ID` | 行号（0–65，部分行为空表示沿用上一条武器） |
| 1 | `ID` | 武器-目标组合 ID（18–93） |
| 2 | `ObjName` | 武器名称（中文） |
| 3 | `WeaponID` | 武器 ID，可多值如 `36,37` / `74,83` |
| 4 | `TarType` | **目标类型**：`0`=间瞄对地, `1`=对车辆, `2`=对人员, `3`=对空 |
| 5 | `ObjBlood` | **目标血量/班数**（1–5） |
| 6 | `AttMin` | 有效射程下限（格） |
| 7 | `AttMax` | 有效射程上限（格） |
| 8–10 | `F0` `F1` `F2` | 特殊标志位（见下） |
| 11–61 | `0`…`50` | **距离（格）→ 攻击力**，共 51 档 |

### `F0/F1/F2` 观测到的取值

- `F0`: `0`（常规）、`100`（便携/重型导弹、车载防空导弹）、`101`（便携防空导弹、中型导弹部分行）
- `F1`: `0` / `1` / `2`
- `F2`: `0` / `1` / `3` / `5`

`F0=100/101` 集中出现在导弹类武器上，推测为**制导/最小射程**相关标志，需实测确认。

### 样例（节选）

```

ID=29  步兵轻武器    WeaponID=29  TarType=2  blood=1  AttMin=0  AttMax=3
       距离 0..3  攻击力: 2 1 0 0
```

**关键观察**：攻击力可出现 **负值**（如重型炮），说明该表承载的是**修正量**而非绝对毁伤，最终裁决需与骰点/CRT 叠加。

## 3. `WuziData.xls`（52 行 × 31 列）

列：`ID, ObjName, WeaponID, ObjType, TarType, ObjNum, ObjAim, F0, F1, F2, 0..20`

与 `WpData` 的差异：用 `ObjType` + `ObjNum` + `ObjAim` 三元组替代 `ObjBlood`。

`ObjType` 取值：`C2`（直瞄炮/速射炮/轻武器）、`A3`（炮射导弹、车载导弹、重型导弹、便携导弹）、`A4`（中型导弹）、`A5`（小型/巡飞/中型导弹）。

样例：
```

ID=69  车载导弹    WeaponID=0   ObjType=A3  TarType=2  ObjNum=0  ObjAim=0  F0=20  F1=1   F2=9
ID=76  巡飞导弹    WeaponID=0   ObjType=A5  TarType=0  ObjNum=0  ObjAim=0  F0=2   F1=1   F2=10
```

**注意**：此表的 `WeaponID` 列多为 `0`，而 `F0/F1/F2` 承载实际参数（如 `20/1/9`）——与 `WpData` 的 `F0/F1/F2` 语义**不同**，不可混用。

## 8. 对自研三维战役引擎的直接影响

### 8.1 可直接复用的语义

1. **武器 × 目标类型 × 目标血量 × 距离 → 攻击力** 四维查表结构。
2. **目标类型枚举**：`0`=间瞄对地、`1`=对车辆、`2`=对人员、`3`=对空 —— **需新增 `4`=对舰**。
3. **装甲类型 5 档**：复合/重型/中型/轻型/无 —— 海上目标可映射为「舰体装甲/无装甲」。
4. **2d6 CRT 裁决机制** + 骰点修正叠加。
5. **高程差修正**（陆战），海上需替换为**海况/浪高修正**。
6. **射程以"格"为单位** —— 自研引擎需改为**以米/公里为单位的真实射程**。

### 8.2 必须新增（引擎完全缺失）

| 缺口 | 说明 |
|---|---|
| 海军域算子 | 无任何舰艇类算子，需从零定义（驱逐舰/护卫舰/两栖舰/潜艇/导弹艇…） |
| 海上武器 | 反舰导弹、舰炮、近防炮、舰空导弹、鱼雷、深水炸弹 |
| 海上目标类型 | `TarType=4`（对舰）、`5`（对潜） |
| 海况/浪高模型 | 对应陆战的高程修正 |
| 固定翼空中算子 | 现有空域仅 aerocraft/drone/helicopter/transport_helicopter/cruise_missile，无战斗机/轰炸机/预警机 |
| 真实装备型号 | 引擎只有武器**类别**，无型号（如"055 型驱逐舰"）。型号层需自建 |

### 8.3 需实测确认（不得臆断）

- `F0/F1/F2` 的确切语义（`100/101` 疑为制导标志）。
- `zm2car_*` / `jm_offset_*` 各维度索引的物理含义。
- `ele_rect_to_peo` 末列恒为 0 的原因。
- 骰点分布（是否严格 2d6）与随机数种子来源。
