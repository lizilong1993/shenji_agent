# docs/ — 跨系统与流程类文档的落点约定

本目录是**跨系统 / 流程类文档**的唯一定稿落点（P3 仓库根）。建立的目的是消除「写到不存在的目录」与「产出物散落临时目录」两类问题（来源：对标任务清单 **P0-6**）。

---

## 1. 三类落点的职责边界

| 落点 | 归属内容 | 示例 |
| --- | --- | --- |
| **本目录（P3 仓库根 `docs/`）** | 跨系统 / 流程类文档：可复现、安全策略、数据字典、部署、评估协议、决策记录、归并报告 | `repo_reconciliation_20261010.md`、`decision_register.md` |
| `situation3d/docs/`（P2） | **仅限 P2（三维态势系统）专属**文档 | UI 主题规范、图层说明 |
| `outputs/`（工作区，非本仓库） | 对外交付与评审材料：给评审/甲方/结题用的报告 | 对标分析报告、任务清单、调研报告 |

> ⚠ **注意两条易错路径**：① `三维态势系统/docs/` 是另一个既有目录（跨系统资料汇总等），**与本目录不同**；② `三维态势系统/situation3d/docs/` **不存在**，勿新建。

## 2. 命名规范

### 2.1 一般规则

```
<主题>.md                     # 长期维护、内容持续修订的规范类文档
<主题>_<YYYYMMDD>.md           # 时点快照类：归并报告、核对表、基线台账、可行性核查等
```

- 主题用小写英文与下划线，不用空格与中文（避免跨平台路径问题）；
- 日期用 `YYYYMMDD`；时点快照**不得覆盖旧文件**，再次生成即新日期新文件；
- 文档内的相对引用一律相对本目录书写；跨仓库引用写全称路径。

## 3. 提交纪律（与本仓库既有约定一致）

1. **显式路径提交**，绝不 `git add -A`；
2. **不提交**大体量交付物与产物：`outputs/` 下的大型报告、`reports/`、`datasets/`、`*.pt`、`.env`（后四者已被 `.gitignore` 覆盖）；
3. 提交前扫密钥（天地图 key、Cesium ion token、`SECRET_KEY`）；
4. 文件必须 **LF**，且不加 BOM。

---

## 4. 复查约定

- 每新增一份文档，须在本文件 §2.2 表格中登记归属条目与状态；
- 每次里程碑复查 `decision_register.md`，关闭项记录依据。

（本约定建立于 2026-10-10，对应任务清单 P0-6）
